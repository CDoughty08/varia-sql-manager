# Execution plan canvas

The Execution Plan output and `.sqlplan` documents share the Pixi viewer. Operators use the workbench icon registry: seeks/lookups, scans/writes, joins, sorts, filters, aggregates, exchanges, scalar operations and spools have recognizable families; unknown operators keep a generic plan icon. Text and strokes use the active theme.

Row flow labels describe the **child's output into its consuming parent**, with arrows pointing toward the parent. Actual values include measured zero; estimates are labeled `Est.` and use estimated executions when available, otherwise say `rows/exec`. Missing runtime rows stay unavailable. Live values explicitly say `Live partial`, including after a stopped execution. Line width is logarithmic and capped; width alone cannot identify provenance. The outline supplies the same row-flow words to assistive technology, even when edge labels are hidden at low zoom.

Select a branch and use **Collapse inputs**, **Expand inputs**, or **Expand all**. Left and Right also collapse/expand inputs before moving to the parent/first input. The virtual outline intentionally lists every operator, including graph-hidden inputs. Choosing an input through the outline, search, rankings or `selectOperator` expands only its ancestors and reveals it. Collapsing a branch selects its root. Models and retained snapshots remain unchanged.

The minimap groups operators into at most 80 × 48 cells. Click or drag to center the viewport; focus it and use arrow keys to pan or Home to fit the batch. It hides when the graph is too small to accommodate it. Its geometry is prepared with topology, not runtime counters; camera changes draw only its viewport marker. It shares Pixi's on-demand frame and does not create another renderer or ticker.

Outline and properties separators accept pointer dragging, arrow keys, Home and End. Their preferred widths, pane visibility, minimap and row-flow visibility use the normal Settings service and `settings.json` persistence. Small panes can shrink below their preferred widths. Camera, selected operator, query, statement/source and collapsed IDs stay in the separate, bounded in-memory view cache across Graph/XML, hidden views and layout moves. They are not persisted plan snapshots.

**Statement SQL** shows compiler-supplied text for exactly the current statement, with Back to graph preserving its selection and camera. It does not guess a location in an edited query, a repeated statement, a procedure or dynamic SQL. **Go to XML** targets the source statement and operator ordinal, verified with NodeId and document revision. It is unavailable for live-only operators without an XML source. Result/estimated/retained sources open their own plan document. Ordinary Graph/XML view switches retain the XML editor's caret/scroll and the graph's selection independently. Moving the XML caret, editing XML or explicitly choosing Go to XML lets Graph map that location to its containing operator, revealing any collapsed ancestors. The lexical lookup runs only on navigation, under the existing XML/operator limits, and handles namespaces, nested statements, comments, CDATA and repeated NodeIds without caching XML copies.

Forced colors uses the outline/properties alternative without GPU preparation. Statement SQL remains available. All pointer actions have toolbar or local keyboard paths; icons are decorative beside operator names. The outline's virtual rows expose selection, position and expansion state, and its description explains that expansion controls the graph while the outline remains complete.

Layout uses threaded tidy-tree contours with iterative traversals in O(operators + edges), preserving SQL Server's document input order and orthogonal parent/input ports. Irregular subtrees can reuse vertical space at different depths. The horizontal gap reserves room for edge labels. Existing viewport culling, stable pooled labels, bounded preparation/layout LRUs, background suspension and incremental counter updates remain in place.

On the existing Windows benchmark harness (Core Ultra 9 285K, Node 24.14.0), a quiet local run measured 3.31 ms p95 for the 2,000-operator wide tree, 13.79 ms for the 10,000-operator four-way tree, and 1.00 ms for cached layout retrieval. These are report-only local measurements, within the existing conservative CI floors. A run concurrent with repository checks was substantially slower; benchmark results are not cross-machine guarantees.

`PlanViewer` exposes optional `controllerRef` (`getCamera`, `setCamera`, `getSelectedOperator`, `selectOperator`) and `onCameraChanged`/`onSelectionChanged` callbacks for linked viewers. Camera objects are copied; invalid camera values are refused. Reapplying an unchanged camera emits no callback. Consumers own correspondence between independent plan models and must pass exact viewer operator identities; the viewer does not match operators or own comparison snapshots.

Regression coverage includes pure navigation/projection/row-flow checks, the maximum-size and irregular forest layout checks, React preparation/live-update checks, and the existing estimated/live/popout Electron suites. Electron checks inspect accessible roles/names and Chromium's accessibility snapshot; a human screen-reader listening pass is not automated.
