Drag a server onto a query tab

Dragging a server from Object Explorer onto a query tab moves that query to the server, as Query › Change Connection… does. Pick a scene; Play the drop runs the animation (the reduced-motion setting swaps the server at once instead).

How it behaves

  • Starts when a server row is dragged. Every query tab shows a dashed socket under it; tabs that are not queries dim. Reordering servers in Object Explorer still works during the same drag, so one gesture does either.
  • Over a query tab the tab lifts and fills with the accent, its socket pulses, and a card names the move: old server struck through → new server, and the database it will use. Hovering does not switch tabs.
  • Dropping runs targets.changeConnection, the same path as Change Connection…: the query's session ends first, and the query opens on the new server's default database (the database remembered for that server when it had one). The tab becomes the active tab and the editor takes focus.
  • The animation (≈ 0.9 s, no layout shift): the drag image flies into the tab and shrinks, a ring in the server's colour spreads from the drop point, a stripe in that colour sweeps across the tab's top edge, the server name rolls over, and the SID badge fades back in when the new session opens. Under reduced motion the server name simply changes.
  • Open transaction: the existing prompt asks Commit, Roll Back or Cancel before the session ends; Cancel leaves the query where it was.
  • Running query: the tab refuses the drop (no-entry cursor, no socket pulse) and the card says to stop the query first. The query is never stopped for you.
  • Same server: refused quietly; the card says the query is already there, so the session and its temp tables are kept.
  • Not a query (Activity Monitor, Table Designer, Properties, Peek, SSIS pages): refused; they keep the server they were opened for.
  • Production: the card shows the server's environment tag; no extra confirmation (the move itself changes nothing on either server).
  • Disconnected servers cannot be dragged onto tabs (their rows offer Reconnect instead). A server dropped on the tab strip's empty space opens a new query on it.
  • Keyboard and screen readers: Change Connection… stays the keyboard path; the drop is announced ("Orders report.sql moved to REPORTING-SQL").

Questions for the owner

  1. Database after the move: the new server's default database (what Change Connection… does today), or the query's current database when the new server has one of that name?
  2. Empty tab-strip space: should dropping a server there open a new query on it (shown above), or do nothing?
  3. Database rows: should dragging a database onto a query tab move the query to its server and that database?
  4. Production: is the environment tag in the card enough, or should moving a query to a Production server ask first?
  5. Animation: keep the full sequence (fly-in, ring, stripe, roll-over, ≈ 0.9 s), or only the stripe and roll-over (≈ 0.5 s)?
