# Changelog

## [Unreleased]

### New and improved

- **Polished Options window:** Tools › Options now opens at `960 × 700` with a resizable navigation rail (`180–340 px`, remembered across sessions). Searching (`Ctrl+E`, `⌘E` on macOS) searches across every page into grouped **Search Results** with match highlighting, tree count badges, clickable page breadcrumbs, and **Modified** filtering with per-row reset (`↺`). **Environment › General** adds **Dark**, **Light**, and **Follow System** theme mode cards plus the palette picker with live preview and custom theme actions; **Fonts and Colors** shows a live Transact-SQL font-size preview; **Apply** saves changes without closing (closing with unsaved edits asks first, and **Reset Page** restores the current page); compact single-line rows keep pages scannable with a hover/focus bottom description panel; **Scripting**, **Commands**, and **Editor Tab and Status Bar** boolean rows use 1-click `True`/`False` switches; and **Shortcuts** uses a slimmer header and inspector.
- **Connect in its own resizable window:** Connect now opens in its own OS window (`900 × 730` by default) with a draggable `320 px` saved-connections rail, remembering its window bounds (falling back safely to default size or recentering if a display is unavailable) and rail width. Favorites are deduplicated out of Recent Connections, live Object Explorer targets show a green status dot, removing a saved entry offers inline **Undo**, newly typed passwords have a show/hide toggle and saved passwords show an inline indicator, **Labels & Custom Properties** stay expanded with quick color swatches, **Advanced** opens inline with live search and a modified-count badge, and the **Connection String** tab adds **Copy** and **Parse & Fill Form** (without importing passwords).
- SQL Server Agent job actions check the listed job's immutable ID, so a replacement job that takes the name is never changed by a stale selection.
- **SQL Server Agent jobs and service from Object Explorer (preview):** With `VARIA_AGENT_PREVIEW=1`, a job's context menu has Start Job at Step…, Stop Job, Enable or Disable, Rename and Delete, and the SQL Server Agent node's has Start, Stop and Restart, which ask first, show their progress and use your Windows account's rights on the server's machine \(Varia on Windows, for a Windows server\)\.
- **Job Activity Monitor (preview):** With `VARIA_AGENT_PREVIEW=1`, Job Activity Monitor on the SQL Server Agent node's menu \(or its node in Object Explorer, or the palette\) lists a server's jobs live, with their status, last run outcome, next run and how long a running job has run\. Tiles count running, failed, between\-retries and disabled jobs and filter to them; view chips, a filter box and column filters narrow the list\. Select jobs to Start, Stop, Enable or Disable them, each as its own request with its own result line, and the Last run chevron shows the selected job's last run below the list\. A job you start is followed in the status bar to its outcome, with Stop, even while the window is hidden, and a separate status bar item says when SQL Server Agent is stopped\.
- **SQL Server Agent Properties (preview):** With `VARIA_AGENT_PREVIEW=1`, the SQL Server Agent node's Properties opens SSMS's General and History pages: the two auto restart settings and the job history log limits, with a table of how long each job's history lasts under the limits now and under the ones you type. History's Delete old history now deletes every job's history older than a number of days, weeks or months after an inline confirmation, separately from OK. Logins below sysadmin, and Managed Instance, see the settings read-only; so does Linux, where mssql-conf sets them and Delete old history still runs.
- **SQL Server Agent job document (preview):** With `VARIA_AGENT_PREVIEW=1`, a job opens in its own tab from Object Explorer, Job Activity Monitor \(double\-click or Enter\), Ctrl\+Q or the palette's Open Job…, with its live state, Start \(or Start once at a step\) and Stop in the header\. Edit its General and Notifications settings, see whether Database Mail can send and when an operator is on pager duty, and remove the alerts that run it; Save sends every change as one transaction, and if someone changed the job since you opened it, nothing is saved and a field\-by\-field comparison lets you reload and keep your changes\. New Job creates a job from blank or as a copy of another, and the Script drawer shows SSMS's script for the save\.
- **SQL Server Agent alerts and operators (preview):** With `VARIA_AGENT_PREVIEW=1`, an alert or operator opens in its own tab from Object Explorer or the palette, and the SQL Server Agent node's New menu creates them. The alert document sets when it fires (an error number, a severity or a performance counter, with the counter's current values), what it does (run a job, notify operators by e-mail, pager or net send, or a new operator made on the spot) and its options, with its history in the header; a job's New alert for this job… starts one that runs the job. The operator document edits addresses and pager duty and sends a test e-mail through SQL Server Agent's mail profile. Operators and Notifications… shows every alert against every operator in one grid you edit by clicking cells, and Add recommended alerts… creates the usual severity and error alerts the server lacks. Deleting an operator can move its notifications to another one, and alert and operator rows have Enable, Disable, Rename and Delete. Alerts need SQL Server on Windows; only sysadmin can change them.
- **SQL Server Agent job steps (preview):** With `VARIA_AGENT_PREVIEW=1`, the job document's Steps page lists a job's steps with where each goes on success and on failure, and edits them beside the list: T\-SQL in an editor that completes against the step's database, with Parse and Open in query window; PowerShell and CmdExec with Run as a proxy; SSIS packages picked from the SSIS Catalog on one page with their parameters and environment\. Drag a step, or use Move up and Move down, and the steps that go to it follow; Delete shows which steps now quit reporting failure, with Undo\. Save writes the steps with the rest of the job in one transaction\.
- **SQL Server Agent schedules (preview):** With `VARIA_AGENT_PREVIEW=1`, the job document's Schedules section edits a job's schedules in place with SSMS's fields, preset chips \(Every day at…, Weekdays at…, Every N minutes and more\), SSMS's sentence and the next five runs in server time, and, for sysadmin, says whether another job runs during this job's usual duration\. Add finds a shared schedule by name or by when it runs \("night", "every 15 minutes"\) with a preview, or starts a new one; a shared schedule names the other jobs it moves and offers Copy for this job only; Remove detaches a schedule, or deletes it when no job uses it, with Undo until Save\. Manage Schedules now opens a Schedules document: a grid of the server's schedules with All, Unused and Disabled views and a filter, an Enabled box that saves at once, and the selected schedule's editor with the jobs that use it, Attach and Detach\. New › Schedule… on the SQL Server Agent node creates one\. Every save checks that nobody changed the schedule since it was read\.
- **SQL Server Agent proxies and credentials (preview):** With `VARIA_AGENT_PREVIEW=1`, a proxy opens in its own tab from Object Explorer \(Enter, double\-click or Properties\), and New Proxy… on the Proxies folders or Proxy… in the SQL Server Agent node's New menu starts one\. One screen sets its name, credential, description and enabled state, the subsystems it is active to and who may use it besides sysadmin, and lists the job steps that run as it\. A new credential can be created right there, with its password typed into masked fields that send it once on Save and keep it nowhere\. A credential opens from Security › Credentials with the proxies and job steps that use it; Change identity and password sends both together, as SQL Server requires\. Proxies can be renamed and deleted from Object Explorer, and the Script drawer writes `<secret>` in place of a password\.
- **Log File Viewer for job history (preview):** With `VARIA_AGENT_PREVIEW=1`, View History on a job, the SQL Server Agent node or the Jobs folder \(also in Job Activity Monitor and the palette\) opens a server's job history as runs, newest first, with each run's steps and the selected row's full message\. Check the jobs to show under Select logs, and narrow the list by window \(24 h, 7 days, 30 days, All\), outcome, message text or step\. Delete History deletes the checked jobs' history, all of it or only rows older than a number of days, weeks or months, after a confirmation\.
- **A job's history in its document (preview):** With `VARIA_AGENT_PREVIEW=1`, the job document's History section shows the job's runs in place: a bar per run for the last 14 runs with the job's usual time \(the median of its last 10 successful runs\), All or Failed runs, and the selected run with who started it, its outcome, its steps and the failed step's full message open, with Copy, Edit step and Start at step\. An SSIS step's execution link opens that execution's SSIS Catalog messages in a query window\. While the job runs, History shows the run live like a CI run: the time so far against the usual time, each step's state and Stop\.
- **Connect to BigQuery:** The Connect dialog's new Server type chooses SQL Server or BigQuery, opening on the one you used last; switching keeps each type's fields, and Undo switches back\. For BigQuery, choose how to sign in \(gcloud credentials, a service account key file or identity federation, picked with Browse…\), see which account that is, then pick the project and default dataset from lists of the ones you can see\. Advanced sets Maximum bytes billed, a service account to impersonate and extra read\-only projects\. BigQuery connections are saved, starred and labelled like SQL Server's and listed by project; a query tab shows the project, account and default dataset, which its Dataset box changes\. Running BigQuery queries and browsing datasets in Object Explorer come in a later update\.
- **Peek's lists are grids:** Peek's Columns and Parameters tabs, and its Index columns, Events, Files, Server roles and User mapping lists, are now grids you can select, sort, filter and copy from, as Query Output's are; in a Peek tab they fill the page and Save Results As writes them. Columns lists each column's type, nullability, key, identity, computed expression and default, and Parameters each parameter's type, direction and default, each with a Definition you can paste into a CREATE statement. Copy on the Properties pane's context menu copies the selected facts, or all of them, as name and value.
- **The column profile follows your selection:** The cards of the columns selected in the grid are highlighted, the active column's card scrolls into view as you move, and clicking a card selects its column in the grid. **Selected Columns Only**, on the panel's filter button or the results ⋯ menu, lists just the selected columns, and holding Ctrl (Cmd on macOS) over the panel peeks at them, or at every column while Selected Columns Only is on, until you let go.
- **Test Connection:** Connect's footer has a Test Connection button that signs in with the form as it is and reports the result inline, with the databases the login can see, without saving anything or opening a connection\. Escape or Stop ends it\.
- **Save says what it does with a password:** With Remember password checked, Save checks a newly typed password with the server, then remembers it; a wrong password saves nothing\. A note under Password and Save's tooltip say what Save keeps, and Save confirms what it saved\. Unchecking Remember password and saving forgets the saved password, as Connect does\.
- **Column filters beside their column:** The list a header's funnel or Alt\+Down opens now sits to the column's right, or its left when there is no room, instead of over the values it filters\. Drag its corner to resize it; the size is remembered and can be set in Options › Query Results › SQL Server › Results to Grid\.
- **Clear all filters from the keyboard:** Ctrl\+Shift\+L \(⇧⌘L on macOS\) in a results grid takes every filter off, as Filter › Clear Filters does\.
- **Column filter actions and selection:** Select all and Select none are now a list of actions beside the values that changes with a search \(Tick the matches, Tick only the matches, Untick the matches\) or a selection, and each says how many values it touches, so a search no longer makes Select none untick only the matches\. Select values apart from their ticks with Ctrl\+click, Shift\+click, Shift with the arrows or Ctrl\+A; Space ticks the selection, and Left and Right move between the actions and the values, so the filter works from the keyboard alone\.
- **GoogleSQL editing:** A query on a BigQuery connection is edited as GoogleSQL, with its own highlighting (backtick names such as `` `my-proj.dataset.table` ``, raw, bytes and triple\-quoted strings, `#` comments, `@parameters`, `STRUCT<…>` and `ARRAY<…>`) and signature help for GoogleSQL's functions as you type `(` or `,` \(Ctrl\+Shift\+Space shows it on demand\)\. Moving a query to a connection of the other engine switches its language and says so; the tab's icon is named GoogleSQL or Transact\-SQL, and hot exit, AutoRecover and Reopen Closed Query keep it\. SQL Server queries are unchanged\.
- **BigQuery queries run:** Execute on a BigQuery connection runs the query as a BigQuery job and shows its rows in Query Output like SQL Server's, with the same row limit, result memory budget and truncation notes, every BigQuery type shown as GoogleSQL writes it (TIMESTAMP in UTC, STRUCT and ARRAY as JSON). Messages name the job and report the bytes processed and billed, with their on\-demand price beside them, the slot time and whether the cache answered; the Results status shows the bytes processed beside the row count\. A query over the connection's maximum bytes billed, a dataset in another location and a result over BigQuery's 10 GB limit each fail with their own message\. A network failure never runs a query twice\. Stop cancels the job in BigQuery \(best\-effort: BigQuery may still bill work done before it stopped\)\.
- **Large BigQuery results read faster:** A BigQuery result of 20 MB or more is read through the BigQuery Storage Read API, in parallel unless the query ends in ORDER BY, into the same Query Output, limits and memory budget, and shown exactly as before\. Reading a query's result this way is free, and it is sent compressed (Zstandard), so it needs a fraction of the bandwidth\. When the Storage API is disabled, not permitted or blocked by a proxy or firewall, Varia reads through the BigQuery API as before and the Messages tab says why, once per connection\.
- BigQuery Script As generates `DROP FUNCTION` for user-defined aggregate functions.
- **BigQuery scripts and sessions:** A multi\-statement BigQuery script shows each SELECT's rows as its own result as soon as that statement finishes, with row counts for the others, and an error points at its line and column in the editor, even inside a selection\. Each query tab keeps its own BigQuery session, so temp tables, variables and transactions carry from one Execute to the next\. Closing, disconnecting or quitting asks Commit or Roll Back for an open transaction, as for SQL Server; what became of a commit that BigQuery refused or did not confirm shows in the tab's Messages, or as a notification once the tab is closed\. Choosing a dataset in another location asks before it ends the tab's session\. An expired session \(24 hours idle or 7 days\) is replaced on the next Execute, saying what was lost\.
- **BigQuery estimates and cost prompts:** A BigQuery query tab shows what the query will process, and its on\-demand price, in a chip beside Execute, from a free dry run after you pause typing; the chip turns amber above the cost threshold and, after a run, shows what the job processed and cost\. The same dry run marks BigQuery's error in the editor at its line and column \(Alt\+F8 goes to it\)\. Execute asks before running a query estimated above the threshold \(10 GiB by default\), with Don't ask again for the connection \(kept with the saved connection; its Advanced Properties turn the prompt back on\), and once per tab when an estimate may be low \(scripts, external tables\)\. Tools › Options › Query Execution › BigQuery › Cost sets the prompts, the threshold, a maximum bytes billed for every query and whether dollars are shown; Sessions explains BigQuery sessions; Text Editor › GoogleSQL turns the dry runs while editing off\. A dry run sends the query text to Google but runs and bills nothing\.
- **BigQuery results larger than memory:** A BigQuery result too large for the result memory budget now stays in BigQuery and is read as you scroll, a few megabytes at a time, instead of being truncated; the Results caption says "windowed in BigQuery", and the Memory panel shows the blocks kept as Window cache. Reading them is free. A result that turns out larger than estimated switches to windowed part way, keeping your place. Tools › Options › Query Results › BigQuery › Results chooses Automatically, by size, Always in memory or Always windowed, and the Block cache per windowed result. Copy and Save Results As work on a windowed result: Copy within the usual Copy limit, and Save streaming every row from BigQuery straight to the file. Load into memory (on the grid's strip and the results toolbar's ⋯ menu) reads a windowed result into memory when it fits the result memory free, keeping your place, so every in-memory tool works on it; Stop leaves it windowed. A result whose BigQuery table expired keeps the rows already shown and offers Re-run, and a windowed cache hit's caption warns it may expire early. Searching, profiles, Pivot and Compare of a result still windowed come in a later update.
- **BigQuery jobs outlive the backend:** Restarting the SQL backend, reloading the window or a backend crash no longer cancels a running BigQuery job, and the restart, reload and crash prompts say so\. Idle BigQuery sessions end when their connection disconnects or the backend stops, so their temp tables stop being billed\.
- **Re\-attach to BigQuery jobs:** A BigQuery tab restored by hot exit or AutoRecover, or whose backend restarted, re\-attaches to the job it was running once it reconnects and shows its results, picking up its session\. Closing, disconnecting, changing the connection of or switching the location of a tab whose job runs asks Cancel the job, Leave it running or Don't close, with Remember my choice \(Tools › Options › Query Execution › BigQuery › Sessions\); a job left running is listed with Copy Job IDs\. Close Results asks the same while a BigQuery job runs, and Leave it running keeps the job in the tab's session for the next Execute to wait on\. Quitting leaves the jobs of tabs hot exit keeps running; after a crash, running jobs with no tab are asked about once \(Cancel Jobs or Keep\), and deleting a saved connection whose jobs still run asks first\.
- **Sort and filter windowed BigQuery results:** A windowed BigQuery result sorts, filters and lists a column's values in BigQuery: each is a query over the result, estimated first with the usual cost prompts, and the grid shows its answer in place of the result, with its job and cost in Messages. A header's funnel lists the column's values, most frequent first, and its checklist, Equals, Between and NULL filters apply in BigQuery; columns BigQuery cannot sort (ARRAY, STRUCT, GEOGRAPHY, JSON, RANGE, INTERVAL) say so on their sort button and have no funnel, and Filter by Selection, duplicates and Keep Selected Rows say they need the rows in memory.
- **Sample a windowed BigQuery result, and re-run an expired one in place:** Load Sample… (on the strip of a windowed result too large to load, and in the results toolbar's ⋯ menu) reads some of a windowed BigQuery result's rows into a new result in memory, named for what it holds ("Sample: 1,000,000 of 52,341,118 rows"), where Pivot, Compare and Column Profile work and keep that name. Its first rows are free; a random sample (TABLESAMPLE SYSTEM) bills only the blocks it reads, and its estimate shows in the dialog before the usual cost prompts. Re-run on an expired result's strip now runs that result's own statement again (a script's statement alone, and never a whole script), after its estimate, and replaces the result where it is instead of running the whole tab. Stop or closing the result cancels either.
- **BigQuery in Object Explorer:** A BigQuery connection now expands to its billing project and extra projects, their datasets, and each dataset's Tables, Views, Materialized Views, External Tables, Routines and Models, down to a table's columns and a STRUCT column's fields, all from BigQuery's free metadata calls\. **Preview Rows** on a table shows its first 1,000 rows without running a billed query; **Script As** writes SELECT, INSERT, UPDATE, DELETE and DROP locally and CREATE from BigQuery's own DDL, after the usual cost prompt; **Properties** shows a table's size, partitioning, clustering and history\.
- **Search Objects finds BigQuery objects:** A BigQuery connection is indexed as it connects, from BigQuery's free metadata calls \(no job, nothing billed\): names first, within seconds, then each table's columns, nested fields and view text and each routine's body\. Search it from Object Explorer's box, a Search Objects tab, the header's Search or All servers beside SQL Server, with chips for materialized views, external tables, snapshots, clones, routines, table functions, models and datasets\. Date\-sharded tables are one result with their shard range, a column shows its type, and a result's menu has Reveal in Object Explorer, Preview Rows, Script As and Copy Fully Qualified Name \(the backtick\-quoted path\)\. Refresh on a project or dataset re\-reads it, and CREATE, ALTER, DROP or UNDROP run from a query tab updates the index when it ends\. Extra projects are indexed by name only unless Options › Object Explorer › Commands › Index BigQuery extra projects' schemas is on\.
- **IntelliSense for BigQuery:** A BigQuery query tab completes projects, datasets, tables, views, routines and columns, down to a STRUCT column's fields, from the connection's Search Objects index, so it answers instantly and runs nothing in BigQuery\. It knows the query's aliases and `WITH` names \(`o.` lists the columns of `orders AS o`\), quotes names in backticks where GoogleSQL needs them, and lists GoogleSQL's functions and keywords\. Hover a table for its columns, rows, size, partitioning and clustering, or a column for its type and description\. The status bar's IntelliSense item says while the index is still reading\.
- **Drag a server onto a query:** Drag a server or database from Object Explorer onto a query's tab or editor to move the query there, as Change Connection does; a card shows what the drop will do, Ctrl \(⌥ on macOS\) over the editor inserts the name instead, and a server dropped on a tab strip's empty space opens a new query on it\.
- Activity Monitor allocates less memory per refresh when calculating rates for Recent Expensive Queries.
- **Search Objects columns and Session Details copy like results:** A table's or view's Columns in the Search Objects details pane are now the same grid as Peek's, with each column's type, nullability, key, identity, computed expression, default and Definition. Activity Monitor's Session Details lists its waits, transactions and locks as grids too (transactions now show when they began). Select cells or press Ctrl+A, then Ctrl+C or Ctrl+Shift+C (⌘A, ⌘C or ⇧⌘C on macOS) to copy them with their headers.
- **SSIS property lists are results grids:** The Packages, Parameters, References and Variables lists in SSIS Project, Package and Environment Properties now work like a results grid: select cells or rows, copy them with or without headers, sort by a column, resize and fit columns, and Save Results As. A sensitive value still shows as stars, and copies and saves as stars.
- **Client Statistics, plan Differences and chart tables copy like results:** The Client Statistics comparison, a plan comparison's Operator differences and Statement differences, and a live chart's View as table are now results grids. Select cells or press Ctrl+A, then Ctrl+C or Ctrl+Shift+C (⌘A, ⌘C or ⇧⌘C on macOS) to copy them with their headers, ready to paste into a spreadsheet; the Client Statistics and plan grids also save through Save Results As. Client Statistics keeps its rows in the report's order; a chart's table fills the plot's place, newest sample first, and keeps its scroll, column widths and selected rows in place as each sample arrives.
- **Copy from the execution plan's outline and Properties:** Ctrl+C (⌘C on macOS) in an execution plan's operator outline, or Copy on a row's context menu, copies the operator as one tab-separated line with its object, estimated subtree cost and rows, ready to paste into a spreadsheet; a header line comes first when Include column headers when copying the results is on. The Properties pane's new context menu has Copy, which copies the selected properties, the one right-clicked or all of them as name and value, and Copy Value, which copies just their values.
- **Comparisons show one row per entry, with a toolbar:** A comparison now shows each row once, a changed value as its old value struck through, an arrow and the new value, and screen readers hear "Price, changed from 5120.00 to 4980.00"\. Each comparison has a toolbar above its grid: links to the two results, ⇄ to swap them, Layout \(One row or Two rows, the old git\-style layout\) and Exact text, each of which changes that comparison in place, keeping its tab, widths and highlights\. Options › Query Results › SQL Server › Results to Grid › Comparisons sets the layout new comparisons use\. A run has one comparison of two results each way round: the Compare popover's button reads Show It, or Update when its Exact text differs, and a comparison with Exact text on is named "\(exact text\)"\. While a compared result is closed, the toolbar's controls are unavailable and say why\.
- **Comparisons: rows, match, chips and notices:** A comparison's toolbar now chooses **All rows** or **Changes only** \(new comparisons follow Options › Query Results › SQL Server › Results to Grid › Comparisons › Rows of a comparison, All rows by default\); with Changes only a dashed rule marks where unchanged rows were left out, and its row number says how many\. A comparison too big for All rows offers Show changes only, in the Compare popover or, once that has closed, in the results toolbar\. **Match** opens a menu to pair rows automatically, by row position, by whole rows or by key columns you tick \(a composite key of up to 16\), and a pair of results remembers its match in the tab for the next time you compare them\. Chips show only the added, removed or changed rows, notices under the toolbar say what matching found \(with buttons to choose key columns or match by position\), a changed column's header is underlined and a key column marked ⚷, and the Column Profile shows each column's changes\. In a narrow pane the toolbar's controls fold into More results tools\.
- **Move between a comparison's differences:** Go to Next Difference \(Alt\+F5\) and Go to Previous Difference \(Alt\+Shift\+F5\) in a comparison's grid, its toolbar's arrows, the grid's menu or the palette step through its changed values and its added and removed rows, wrapping round, and the toolbar and screen readers say "Change 2 of 31" \(of the rows shown, under a chip or filter\)\. Go to Possible Match on a row marked ? selects the look\-alike row it names\. A strip beside the scroll bar marks where the changes are; press a mark to scroll there\.
- **Copy rows from editable grids:** Ctrl+C (⌘C on macOS) or Edit › Copy in Table Designer's columns, New Database's files and filegroups, Restore's backup sets and files, Attach Databases, a login's User Mapping, Securables, Explicit permissions and Mapped Credentials, Table Properties' Extended properties and the Shortcuts table copies the selected rows as tab-separated text, ready to paste into a spreadsheet, with a header line when Include column headers when copying the results is on. With text selected in a field, it copies that text as before.
- **Search Indexer in Nerd metrics:** The Memory panel's Nerd metrics now show what the Search Objects index holds, below the results: how many definitions are packed and how much memory that saves, where the index budget goes (records, names and definitions), how much text databases and connections share, what was left out, and the last build's and search's times.

### Changes to everyday use

- **Larger results fit in memory while they load:** A result is now compressed as it loads, once it passes 1 MiB, instead of only after it finishes and sits idle. A single result can therefore be at least twice as large, and often several times larger depending on how well its data compresses, before it reaches its memory limit and is truncated. Loading takes as long as before.
- **Copy and save have their own column header settings:** Options › Query Results › SQL Server › Results to Grid now has **Include column headers when copying the results** (off by default) and **Include column headers when saving the results** (on by default) instead of one setting for both, so Save Results As writes a header row unless you turn it off. If you had turned the old setting on, both new settings start on; otherwise saves now include column headers until you turn the save setting off. SSIS Operations' Copy now follows the copy setting too. Copy with Headers still always includes them, and JSON always names its keys.
- **Properties lists are results grids:** Table Properties' Permissions, Partitions and Security Predicates, and Database Properties' Files and Filegroups, are now drawn like query results: select cells, rows or columns, copy with or without headers, sort by a header, resize or fit columns, and Save Results As from the grid's menu. Long values no longer wrap; widen the column or copy the value. Numbers (partition rows, file sizes) show without thousands separators, as in query results.
- **A comparison marks guesses:** When a key repeats, a comparison pairs its rows in order and its gutter shows ≈ (repeated key) on them; a removed and an added row that look alike, most of their other values equal, show ? and name each other as a possible match, without changing the counts or colours. A row with more changed values than its gutter can list says "More changes in this row are not listed".
- **A comparison's colours show under the selection:** In a comparison, only a changed row's changed values are coloured, struck through on its old row and bold on its new one; added and removed rows keep a faint wash and unchanged rows none. Highlights, search matches and the selection now lie over these colours instead of replacing them, in every results grid, so a selected or highlighted change stays visible. Selected cells and search matches are a lighter, translucent tint. Selected cells keep their own text colour. Theme authors: selected grid cells use the new translucent `resultsGrid.selectionOverlay` and `resultsGrid.inactiveSelectionOverlay` keys and search matches `resultsGrid.hitOverlay`; `resultsGrid.selectionBackground` and `resultsGrid.selectionForeground` now colour only Table Designer rows, and `resultsGrid.inactiveSelectionBackground` is no longer drawn.
- **A comparison's marks and row numbers move into the gutter:** A comparison now shows only the compared columns. Each row's header draws a bar for its kind, its − or + mark and its number in its own result, and names the kind and both rows for screen readers and in its tooltip. The Change, R1 and R2 columns are gone, so a comparison can no longer be sorted or filtered by kind or row number, and Copy leaves them out; Save Results As still writes them, as Change, Old row and New row, before the data.
- **Comparisons named for themselves:** A comparison's Column Profile is titled Column profile with the comparison's name under it, and its grid, splitter and the toolbar's progress name it the same way to a screen reader and on screen, instead of a "Result 3" seen nowhere else; a Pivot's are named for the Pivot. A comparison's tab reads old → new ("Result 1 → Result 3"), long names shortened in the middle, with the full name in its tooltip.
- **The window reopens where you left it:** Varia's main window opens at the position and size it was closed at, maximized if it was. If that place is no longer on a screen (a monitor was disconnected, or a display's resolution, scale or arrangement changed), it opens on the nearest display instead, fitted to it; a window closed minimized or in full screen reopens as a normal (or maximized) window. On Linux under Wayland only the size and maximized state come back.
- **Expanding shows the children:** Expanding a node in Object Explorer scrolls to show as many of its children as fit, without scrolling the node out of view.
- **Auto-expand single children:** Expanding a node whose only child can expand keeps going down to the first node with more than one child and selects it, so Down Arrow lands on its first child; it never opens a System folder. Turn it off with Tools › Options › Environment › Object Explorer › Auto-expand single children.
- **Ctrl+F in Object Explorer:** With focus in Object Explorer, Ctrl+F (Cmd+F on macOS) jumps to its search box, as Ctrl+Shift+F does. In the query editor Ctrl+F is still Find.
- **Sorted and filtered grids are compressed too:** A large result on screen whose grid is sorted or filtered is now compressed once idle like any other, and packing to make room for a new query can take it. Scrolling it reads the compressed pages a few milliseconds slower a jump, which reading ahead hides while you scroll; while result memory is full, as when a new query needed the room, a jump takes tens of milliseconds. Find searches it as it is.
- **Search Objects knows column types and keys:** The Search Objects index now also keeps each column's and parameter's type and flags, and each index's, key's and foreign key's columns, ready for the query editor to use. It adds roughly 15 bytes per column or parameter, so on a server near the index's memory limit a very large database may be kept without its columns a little sooner. Searching is unchanged.
- **Search Objects holds more definitions:** With definitions indexed, those of 512 characters or more (procedures, functions, views, triggers, plan guides, and long constraint and computed column expressions) are kept compressed, at about a seventh of their former size, so far more of a large server's definitions fit before Search Objects starts leaving them out. Results are unchanged. A search inside definitions takes about four times as long, still well within its time limit.
- **More rows fit in result memory:** Compressed results take less memory, so more of them fit before Varia has to make room: about a third less for a typical query and for results of numbers and dates, less for long text. Scrolling a compressed result is as quick as before; a sorted view's screen of it takes a millisecond or two longer.
- **Smoother scrolling of a sorted compressed result:** Scrolling a sorted or filtered grid of a large compressed result, and Find in it, now reuse the memory each read unpacks into instead of allocating it anew, so scrolling no longer pauses for memory clean-up every other screen.
- **Animations play unless you ask Varia to follow the system:** Menus, dialogs, hover fills, spinners and the live dot now animate even when the operating system asks for reduced motion. To have Varia follow that preference again, turn on Tools › Options › Environment › General › Reduce motion when the system asks; popouts and dialog windows follow it too.
- **New profile file names, and 0.9.0 still opens its own:** Saved connections, remembered passwords, the reopened session and AutoRecover copies now live in new files (`mssql-connections.json`, `mssql-saved-passwords.json`, `WorkbenchSession` and `WorkbenchAutoRecover`), ready for connections to other database engines. The first start copies 0.9.0's files and never changes them, so going back to 0.9.0 opens your connections and tabs as they were when you upgraded; what you change afterwards stays with the newer version.
- **Faster Find in text that is not English:** Find in Results and the column filter's value search look through accented and non-English text in a column with a linguistic (not binary) collation about three times faster, finding exactly what they found before.
- **Find skips what cannot match:** Find in Results now passes over the compressed parts of a large idle result that cannot hold the text, without decompressing them, so looking for a specific name, number or word takes up to about half the time; common words such as "error" take as long as before. The answers are the same; the index this keeps adds about 5% to a compressed result's memory for typical text, and never more than an eighth.
- **Find keeps up as you type:** Each key typed into Find in Results or a column filter's search now looks only through the rows (or values) the text before it could still match, and Find Next and Find Previous look only through the matches, so a large result answers sooner as the text grows: typing a word into SQL Server's own messages in every language takes about half the time, and a third or less in English text. The answers are the same as a full search; text Varia cannot safely rule out (such as Japanese and Chinese punctuation, or a language that reads two letters as one, like Czech ch) is searched again each key.

### Fixes

- **AppImage updates keep the working version:** If the updated AppImage cannot start \(for example on a system without a library the new release needs\) or stops within 30 seconds, before it has started, Restart to Update now puts the previous AppImage back instead of leaving only the new one\.
- **Reloading a changed file keeps what you type meanwhile:** Text typed into a query while Varia reads its file again, after the file changed outside Varia, is no longer replaced without asking: File changed asks first, as it does for any query with unsaved changes\.
- **Recovered queries keep outside edits to their file:** After Recover Unsaved Queries reopens a query, Save asks before replacing edits another application made to its file while Varia was closed\.
- **Find in Results keeps the active match highlighted:** Stepping back to a match already shown while the next page of matches was still loading \(for example Next right after Previous wrapped from the first match to the last\) no longer leaves the count on a match with no cell highlighted, or says the search failed when it had not; with many grids of matches, each step is also quicker, as it moves only the active match instead of rebuilding every grid's matches.
- **Move Commas leaves BigQuery queries alone:** Move Commas to Front and Move Commas to End are now available only in SQL Server queries\. They read the query as Transact\-SQL, so in a GoogleSQL query they could move a comma out of a `#` comment and change what it means \(`SELECT a # total,` on one line and `b` on the next became two columns instead of `a` named `b`\)\.
- Recovered file-backed queries keep their unsaved marker when their contents were deleted. Save All includes the empty file, and closing the tab asks before discarding the edit.
- **A GO: label runs:** A line that starts with the label `GO:` is now run as part of its batch, as SSMS and sqlcmd do, instead of being rejected as an invalid GO; `GO :`, with a space, is still rejected.
- **Toggle Brackets leaves GoogleSQL alone:** Toggle Brackets is now available only in SQL Server queries, so it no longer rewrites a BigQuery query's array brackets (`SELECT [a]` became `SELECT a`, a scalar).
- **Toggle Brackets keeps JSON functions valid:** Toggle Brackets no longer brackets `ABSENT` in `ABSENT ON NULL` or `RETURNING` in the JSON functions \(`JSON_ARRAY(1, NULL ABSENT ON NULL)` became `[ABSENT] ON NULL`, a syntax error\); a column named `absent` or `returning` is still bracketed, and so is now a key before its colon \(`JSON_OBJECT(k:v)` becomes `JSON_OBJECT([k]:[v])`\)\.
- **Execute To with an @RC parameter:** Script As › EXECUTE To on a procedure or function with a parameter named `@RC`, or one a collation compares equal to it (such as a fullwidth `@ＲＣ`), now names the return code `@RC1` (or the next free number), instead of declaring `@RC` twice so the script failed with error 134.
- **Script As SELECT on a scalar function runs:** SELECT To on a SQL Server scalar or CLR scalar function now always names its schema, even with Schema qualify object names off, since SQL Server rejects a one\-part scalar function call \(error 195\); table\-valued functions still follow the option\.
- **Table Designer follows the database's collation for column names:** The designer no longer refuses column names the database tells apart, such as `I` and `i` in a Turkish database, `c` and `ç` or a Swedish `a` and `å` in accent\-insensitive ones, or `ch` and `cH` in a Czech one\. Names the database treats as the same, such as `Id` and `ID` in a case\-insensitive database or `I` and `ı` in a Turkish one, are refused by Save before the table is created, with the cursor on the column to rename, and Generate Change Script warns about them; only names differing in trailing spaces are flagged as you type\.
- **Parameter defaults on a case\-sensitive server:** Object Explorer and Peek no longer show one parameter's default on another whose name differs only by case \(`@x` and `@X` on a case\-sensitive or binary server collation, or `@i` and `@I` on a Turkish one\); each parameter shows its own default, or none\.
- **The Backup Timeline offers only points it can restore to:** When a log backup is missing, the logs after it are no longer shown as covered and their times can no longer be chosen, since no restore plan reaches them; coverage returns after a later full or differential backup that bridges the gap\. Under Manual Selection, the band and OK follow the checked backup sets, so OK no longer accepts a point they cannot stop at\. Last backup taken shows the real last backup even while a point is set\. Specific date and time starts at the last backup taken, and the timeline stays put while you move the point inside it, sliding only to keep the point in view\. Moving the point on a long backup history is also quicker\.
- **Restore Database no longer hangs on a long broken log chain:** When the full backup is missing or cannot be read, or a missing log cuts the logs after it off from the full, Restore Database now chooses its plan at once instead of hanging for a minute or more on a history of about a thousand backups\.
- **A query never runs in the wrong database:** With `SET NOEXEC`, `PARSEONLY` or `FMTONLY` left on in a query tab, choosing another database and executing a script that turned the option off ran it in the previous database, because SQL Server skipped the database change \(`SHOWPLAN` skips it too\)\. Varia now checks the change took effect; if not, it runs nothing and names the options that cause this\.
- **Restore to a new database with CREATE DATABASE in master:** Restore Database no longer refuses a login whose only right is `CREATE DATABASE` in master, which SQL Server accepts for restoring to a new database; before, it asked for `CREATE ANY DATABASE`, dbcreator or sysadmin.
- **Restore checks it is restoring the backups you reviewed:** Restore Database and Restore Files and Filegroups now check, before the run and again right before each backup set's RESTORE, that the set is the one the plan was made from \(its backup set GUID\), not just a backup of the same kind at the same position\. If a job overwrote a backup file after it was read, the restore stops at that set and asks you to read the backups again\.
- BigQuery BOOL cells order false before true in sort, filters, Pivot and column profiles, and save as Boolean literals in JSON.
- **Empty text is not zero in a comparison:** Comparing a number column with a text column of the same name no longer treats empty text, a lone `-` or `.`, or other text that is not a number as 0 when the number is in the old result; the result is the same whichever way round you compare\. Trailing spaces after a number are underlined, or changed with Exact text, as in text\.
- BigQuery Pivot sums and averages include fractional NUMERIC and BIGNUMERIC values at their full scale.
- **float and real values that show the same stay apart:** Two float or real values that differ beyond the 15 or 7 digits the grid shows \(1E0 and 1.0000000000000002E0 both show as 1\) are no longer treated as one value: they sort in their true order, a filter keeps only the value you picked, the funnel and column profile count them apart \(the funnel shows a rounded value's exact digits\), and Compare marks them changed\. The grid, Copy and Save Results As still show the rounded text\.
- **Save checks a changed file's contents, not just its date:** Save now asks before replacing a query or execution plan file that another program changed, even when a sync or copy kept the file's size and modification time\. It asks again if the file changes while a Save question is open\.
- **Save keeps a new connection:** Saving a connection that has never connected no longer loses it\. It stays in History's new Saved group until it connects\.
- **Escape always closes Connect:** Clicking Save, a History row's star or Remove, Add favorite, Register server or a blank part of the Connect dialog no longer leaves the keyboard outside it, so Escape and Tab keep working without tabbing back in\.
- **Connect asks before dropping a new connection:** Closing Connect after filling in a connection that is not saved yet, or changing its name, color, environment or settings, now asks whether to save it to History \(Save, Don't Save, Cancel\), as it already did for saved connections\. A typed password alone does not ask\.
- **Consistent controls:** Query toolbars, Connect and Options share the same styles for selects, text fields and buttons, with compact variants in dense rows. Query connection pickers keep their focus rings flush with the connection pill. Narrow Object Explorer and Results panes give their tools a second row, and Connect opens wider with footer buttons sized to fit their labels.
- Search Objects highlights the matching line in a definition when the SQL contains tabs, including when a later line uses spaces.
- **Esc closes Peek in the query editor:** Esc in a query now closes a Peek card opened by holding Ctrl (Cmd on macOS) over a name in it or over an Object Explorer row, which left focus in the query and ignored the key, and cancels an Alt+F12 peek still looking the name up. Suggestions and Find still close first.
- BigQuery timestamp columns sort and group by their UTC instant, including values a microsecond apart.
- **Find in a sorted grid keeps a compressed result compressed:** Find through a sorted grid no longer decompresses the whole result first, so it needs no room in result memory for the result's full size and is no longer refused for want of it.
- Search Objects finds whole-word wildcard matches when an identifier contains the pattern's ending more than once.
- Search Objects finds whole-word regular expression matches that end later in the same identifier, so `Order.*?Id` with Match Whole Word finds `OrderIdArchiveId`.
- Escape right after Save in Connect now stops Save's password check: focus moves to Cancel as the check starts, instead of leaving the dialog for a moment while Save is disabled.
- **Dropping a server below the last one:** Dragging a server in Object Explorer past the last server and releasing it there now moves it to the end, instead of cancelling the move. The drop line always shows where the server lands: below the tree's last row, and above an expanded server rather than under its name, and it no longer lingers over loading and error rows.
- **Search Objects marks all of a long definition match:** A definition match longer than its preview now has every character the preview shows marked, instead of only a few at the preview's end.
- **Closing a query tab while it starts a command no longer leaves its connection open:** Closing a query tab, or disconnecting its server, just as an execute, commit, estimated plan or transaction check started on it could leave the tab's SQL Server connection open instead of closing it. It is now always closed.
- **Comparing very wide results no longer stalls:** For results with thousands of columns, the Compare menu and toolbar no longer freeze, and a comparison no longer spends seconds, while working out which columns pair\.
