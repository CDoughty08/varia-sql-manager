# Changelog

## [Unreleased]

### Added

- **Named results:** put `/* #Name="Open orders" */` or `-- #Name="Open orders"` just before a statement to name its result: the result's tab and caption, the Go to Result list and the Compare popover show the name instead of "Result 2", and results without one keep their numbers. Stacked markers before an `EXEC` name its result sets in order, and `GO 3` names each repetition's. The query runs exactly as written. Where Varia cannot tell which result set a statement returns (inside `BEGIN … END`, a branch or a loop, after an `EXEC` or `IF` in the same batch, or after an error in the batch), the name is not applied and the Messages tab says why.
- **Result names on every results surface:** a named result shows its name on its result tab and Stacked caption, in Go to Result and the overflow picker, the Compare popover, its Pivot's title, builder and Out of date sentences, comparison titles and links ("Open orders (closed)" once closed), Column Profile, splitters, plan labels and the Memory panel, and its grid's accessible name starts "Open orders, Result 2 of 5". Lists, tooltips and accessible names keep the number beside the name, and a Pivot or comparison made from one of two results of one name adds its number ("Pivot of Totals (Result 3)"), so they are told apart; the filter matches either; an unnamed result reads as before, and Go to Result 1 to 8 still count places. A tab that shows a name (a named result's, or a Pivot's or comparison's made from one) is at most 240 pixels wide, and a long name, in a tab or a caption, ends in an ellipsis with the whole name in its tooltip; tabs and captions of unnamed results are unchanged. The query a first launch opens names its result ("Sample Query").
- **Progress for long result operations:** a sort, filter, column profile, Pivot or comparison that takes a while shows its phase, a percentage that only goes up and Cancel in the results toolbar; a sort or filter also shows a ring on its column and a bar along the grid. Sorting, filtering, Save Results As and Sort Text By wait for it instead of piling up (a click is refused, not queued), Copy still works, and Cancel or Escape keeps the grid's previous order and rows.
- **Table Properties:** choose Properties on a table in Object Explorer, or Properties in a table's Peek tab (Open as Tab), for SSMS's Table Properties as a document: General (with lock escalation and temporal and ledger facts), Permissions, Change Tracking, Storage (compression, filegroups, partitions, rows and space), Security Predicates when a row-level security policy names the table, and Extended Properties. Apply changes lock escalation, change tracking (and Track columns updated) and extended properties in one transaction that rolls back entirely on a failure or Stop, asks before turning change tracking off, and Script shows the same statements. SQL Server's own, external and dropped ledger tables are read-only. Quoted identifier is not shown.
- **Connection restoration:** remember Object Explorer connections and each query's exact target, database and attachment preference across hot exit and reload. Previously connected servers attempt reconnect by default, with a global option and per-connection override; an explicit Disconnect stays respected. Background reconnect preserves credential choices and the previous account, leaves failures disconnected, and never opens browser sign-in or runs query text.
- **Connection targets in Object Explorer:** retain collapsed disconnected roots, reconnect in place, and use separate Disconnect, Disconnect and Remove from Explorer, and Remove from Explorer actions. Equivalent connections reuse one root; changed presentation or startup reconnect details receive an explicit confirmation.
- **Disconnect with query tabs:** choose whether to keep tabs, close query tabs, or cancel. Save and transaction decisions are resolved before tabs close, running-query cancellation is explicit, and retained results keep their original session provenance. Dependent document drafts remain open and follow only their exact connection target.
- Hold Ctrl and scroll the mouse wheel over the query editor to increase or decrease the editor font size.
- **Getting Started:** read offline connection, query and results guides with live shortcuts, option values and mouse gestures, plus interactive fictional examples. Open it from Help or the command palette. Navigation stays available if a guide cannot load.
- **About Varia:** find the running version, platform and update status from Help or the command palette (also the app menu on macOS). Copy version details for support and open the project, issue form or release notes without needing a server connection.
- **In-app release notes:** read curated release highlights and limits offline, browse bundled history and open notes for the exact version advertised by an update. Missing notes are reported clearly, with release downloads available separately.
- **Activity Monitor session details and Kill Process:** right-click a session in Sessions, Blocking or Active Expensive Queries for Details… (its state, current statement, batch, last batch, waits, transactions, tempdb usage and, on request, locks, beside the monitor, with Copy) or Kill Process…, which asks first, names the session's login, host and open transactions, warns about rollback, and reports what happened. Kill is refused, with the reason, without ALTER ANY CONNECTION, and is never offered for Varia's own pooled connections.
- **Activity Monitor Recent Expensive Queries:** see the statements that finished since the previous sample, grouped by query hash with per-second rates, and rank them by CPU, duration, reads, writes or executions. The plan cache is read only while the pane is shown, at its own interval (Settings › Activity Monitor › Query statistics interval, 30 seconds by default). A rank chip or column sort reorders the rows at once, without waiting for the next sample or reading the server again; so does a column sort in any live grid.
- **Activity Monitor Resource Waits and Data File I/O:** see where the server waits, by wait category or by wait type, with a 1-minute average and benign waits hidden by default, and each database file's throughput, read and write latency, response time and size. Files over the I/O latency thresholds (Settings › Activity Monitor) are highlighted, and Over threshold, Rows and Log narrow the list. Both panes read one sample, every 5 seconds by default, only while either is shown.

- **Keep Selected Rows:** filter a results grid to exactly the rows you selected, from the grid menu's Filter submenu. It works on sorted and filtered grids, pivots and comparisons, combines with other filters and sorting, and shows as one removable "12 selected rows" filter. Up to 4,095 rows.
- **Copy and save a transposed view as shown:** a results grid drawn transposed (its columns as rows; the commands that turn a grid this way follow) now copies and saves what it shows, with nothing stored: a line per column and a value per row, in the grid's sort and filters, for Copy, Copy with Headers and Save Results As in every format. With headers the first line reads Column, Row 1, Row 2…, or the values of the column used as headers (a repeated value gets _2, _3…). The first 4,095 rows are written, and the toolbar says how many were left out.
- **Discard results after execution:** Tools › Options › Query Results › SQL Server › Results to Grid can run queries without keeping their rows, as in SSMS: every row is still read from the server, the Messages tab says how many result sets and rows were read and not kept, and execution plans and client statistics are still collected. Useful for timing a very large query. While it is on, the status bar says **Results discarded** (click it to open the setting in Options), and a run that kept no rows says so where its grid would be, with **Turn off Discard results** and then **Execute again**, so queries that seem to return nothing, Select Top 1000 Rows included, have a visible reason.
- **Close one result:** each result's caption has a close button that frees that result's memory and leaves the others as they are, with their names, numbers, sort and filters. Closing a result closes its Pivot with it; a Pivot or a comparison closes on its own, and comparisons made from a closed result stay. **Close Just This Result** in the grid menu (Close Result in the command palette) does the same. Closing the last one keeps the Results view, Messages and captured plans, and Close Results stays to release them; Find, Save Results As, Pivot, Compare and Transpose are then unavailable, and the Pivot builder closes, as the Compare popover does.
- **Grouped results:** each result now owns its Pivot, drawn directly under it, with comparisons after the results. A result has one Pivot, always built from the result itself: the Pivot builder names the result it belongs to and follows the grid you last used (the source picker is gone), each result keeps its own draft, and building again replaces the result's Pivot. Pivots of pivots and several pivots of one result are no longer possible.
- **Pivot replaced in place:** building a result's Pivot again keeps the old one on screen until the new one is ready, then swaps it in the same place, keeping the focus, the transposed view and the sort and column widths of columns it still has; a build that fails, is cancelled or does not fit in result memory leaves the old Pivot as it was and says why. Pivot Results… on a Pivot reopens what it was built with. Pivots of different results now build at the same time (up to four at once), a busy SQL backend is asked again a few times before giving up, and a Pivot's strip says when its result holds only part of the query's rows.
- **Out-of-date Pivots and Update:** when you filter a result after building its Pivot (or remove or change a filter), the Pivot's caption (in Tabs layout, the row above its grid, with a dot on its Pivot tab) shows "Out of date" with **Update**, and its strip says the result's filters changed since it was built; sorting does not mark it, nor does filtering again by the same values (ticking them again in a column's filter, or selecting other cells that hold them). Update (also **Update Pivot** on the grid's menu, where Pivot Results… now has no access key, and in the command palette) builds the Pivot again from what it was built with over the result as filtered now, keeping the old one on screen until the new one is ready, and offers Cancel while it runs. An Update that fails, does not fit in result memory or is cancelled leaves the old Pivot and says why in the results toolbar.
- **Pivots follow their result's filters:** a Pivot you can see rebuilds by itself when its result's filters change, if the result stores at most 500,000 rows and the Pivot's last build took under 250 ms; larger or slower ones stay marked out of date with **Update**. A Pivot that is hidden (in Tabs layout, another view selected; stacked, its caption collapsed; the Results panel hidden, as when Messages takes its place) keeps its mark and rebuilds when you show it. A newer filter change stops the rebuild still running, so only the last is shown, and a rebuild that fails, does not fit or is cancelled leaves the old Pivot marked and is not tried again until the filters change.
- **Results as tabs:** the results toolbar's **Tabs** shows one result at a time: a row of tabs for the query's results and comparisons, the selected result's Table and Pivot as view tabs beneath, and one grid. Switching keeps every grid's scroll, column widths, selection, sort and filters; Find Next selects the tab that holds the match; each tab closes its view, and the focus moves to the next tab. The Messages strip opens beside the tabs when there is room. Also **Show Results as Tabs** in the command palette and the Window menu, and the **Show results** setting. Tabs is now the default; turn it off for Stacked.
- **Go to Result and Next Result:** in Tabs layout, a button at the end of the row of result tabs counts those out of view and opens a list of every result, Pivot and comparison with a filter box; Enter or a click shows the one picked. It stays quick with 1,000 results. **Go to Result…** (**Ctrl+Shift+O**) in the command palette and the Window menu opens it too. In the Results pane, with two or more results, browser tab keys move between results: **Ctrl+Page Down** and **Ctrl+Page Up** step (Windows and Linux), **Ctrl+1** to **Ctrl+8** pick one and **Ctrl+9** the last (⌘ on macOS); otherwise (Messages and the plan too) the same keys pick query tabs, like a browser's. Go to Result and Next Result bring the Results pane back if it was closed or hidden with Ctrl+R. **Ctrl+Alt+Page Down** and **Ctrl+Alt+Page Up** (Next and Previous Result) step through the results from anywhere, in Stacked too, which scrolls to the result; with **Shift** (Next and Previous Result View) they switch a result between its Table and Pivot outside text. A short results pane folds the rows of tabs so the grid keeps its rows. Ctrl+1 to Ctrl+9 are no longer kept for SSMS's query shortcuts.
- **SSMS query shortcuts in the command palette:** **New Query with sp_help**, **New Query with sp_who** and **New Query with sp_lock** stand in for SSMS's Alt+F1, Ctrl+1 and Ctrl+2. Each opens a new query, connected as New Query would be, holding the `EXEC` call; it does not run until you execute it. As in SSMS, `sp_lock` is not available in Azure SQL Database. They have no keys: Ctrl+1 to Ctrl+9 (⌘ on macOS) now pick query tabs and results, and Alt+F1 opens the desktop menu on some Linux desktops.
- **Compare popover:** **Compare…** in a results grid's menu (Compare Results… in the command palette, or the results toolbar's Compare) opens a small popover beside the grid or the toolbar button: choose which of the run's other results to compare with (with only one, there is no list), swap old and new, choose Exact text, and press Enter. It lists the columns that will not be compared, and warns that sorts and filters are not applied, only when that applies; it remembers the last choice made on each result, even across re-runs; Escape or a press outside closes it, and it closes once the comparison opens. Only results the query returned are offered, never Pivots, comparisons or plan sets. Comparisons of different results run at the same time, at most four at once together with Pivot builds, and a comparison's strip now links to the two results it compared, or says one was closed.
- **Larger results:** query results can now use a quarter of the computer's memory up to 16 GiB (it was 2 GiB), half of it for one query, so a query of several million rows keeps them all on a machine with the memory for it. Tools › Options › Query Results › SQL Server › Results to Grid has a **Result memory limit** to set it yourself, and a **Maximum rows kept per execution** for when you only want the first rows. The limit applies as soon as Varia has read its settings, even after a read that failed, and a change to it applies at once, without restarting the SQL backend, and the status bar's memory meter follows it; lowering it below what results hold keeps them and stores nothing more until enough are closed. A truncated result names the budget it filled, even after the limit changes.

- **View Dependencies:** right-click a table, view, procedure, function, trigger, synonym, sequence or type in Object Explorer for View Dependencies, as in SSMS. Object Dependencies lists the objects that depend on it, or those it depends on, as a tree read one level at a time as you expand it, with each node's name, type and dependency type (schema-bound, non-schema-bound or foreign key). A table's or view's own triggers are listed as depending on it, and it as what they depend on, in Peek's Dependencies tab too. A cycle is marked rather than followed; objects in another database or on a linked server are shown but not followed; a level of more than 500 objects says so. Enter or a double-click selects the object in Object Explorer, and Peek opens it in a Peek tab.

- **Nerd metrics in the Memory panel:** open Nerd metrics under the status bar's Memory breakdown for what results hold as read and in memory, the largest results by name, the page codec's counters and the managed heap. It starts collapsed and remembers whether you opened it, and shows compression's figures as results are packed (below); the breakdown is a little wider to fit it.
- **Go To Definition:** press **F12** on a table, view, procedure, function, synonym or user-defined type in a query (or on a column, for its table) to script it as CREATE to a new query tab, as in SSMS. **Alt+F12** opens it in Peek, and **Ctrl+click** does what F12 does. Both keys also work in Peek's definition editor, and a name that matches nothing only shows a status-bar message.

### Improved

- **Search Objects uses less memory:** the index keeps each object in 24 bytes instead of 136, besides its names and definitions, so it holds about 2.4 times as many objects per megabyte without definitions and about 30% more with them. Large databases are indexed with their columns, keys, indexes and parameters more often, instead of without them. Searches find the same objects, in the same order, as fast as before.
- **Results take less memory:** a result of 1 MB or more that no window has shown for 5 seconds, or that is on screen but has not been read, copied or saved for 30 seconds while its grid is neither sorted nor filtered, is compressed in the background, typically to a third or half of its size, and the room it frees goes back to result memory at once, so more results fit. Nothing is dropped or written to disk. Showing it again, scrolling, a plain Copy or Save, and sorting, filtering, profiling, pivoting, a column's value list, highlighting rows, a comparison or a search read it as it is; a search through a sorted grid, a comparison that reads one result in a very different order from the other, and a transposed Copy or Save first unpack what they read, which needs room for its full size and says so when result memory is too full (more likely now that a result on screen can be compressed and its room taken by another query). Sorting or filtering a compressed result on screen unpacks it again when there is room. A query that fills result memory waits briefly (its grid pauses meanwhile) while other results are compressed to make room, and only then stops storing rows, so more rows fit before truncation; a sorted or filtered grid on screen, or a result just unpacked for a search, is not compressed for it. Results still loading and live views are never compressed. The Memory panel's Nerd metrics show what was packed and saved, and a result whose packing stopped part way shows as Partly packed.
- **Lighter startup:** opening Varia no longer starts the SQL IntelliSense service for the untouched welcome query, which saves about 110 MB of memory for the first minute. Error checking begins with your first edit.
- **Runtime:** the SQL backend now runs on .NET 11 (it was .NET 10). Nothing to install: Varia ships the runtime with the backend. Building from source needs the .NET 11 SDK.
- **Transposed is now a view, not a copy:** Transpose Results draws the same grid with its columns as rows and turns it back again, instead of adding a new result. It costs no result memory, works while rows are still arriving and on a query whose result memory is full, and follows the grid's sort, filters, selection and highlights. Transpose Selected Rows keeps the selected rows as a filter first. Using Column as Headers is a setting of the view, changed from Headers beside the toolbar button. The first 4,095 rows are drawn as columns, with a strip that says so. Shortcuts assigned to the three commands keep working. Copy and Save Results As write the grid as drawn. The transposed names and rows can no longer be sorted, filtered or profiled as a result of their own.
- **Results:** the Results tab's badge counts the query's own results, not their pivots or comparisons. After a re-run, commands act again on the result whose grid you last used. Peek's top rows show the grid alone, without a caption, and no longer offer Pivot, Compare or Close Results, which did nothing useful there.
- **Results:** the run summary's row count is the rows the query returned; a pivot or comparison no longer adds its rows to it. A result added after you drag a splitter no longer resets the other results' heights. Search in results looks again only at the grids that changed.
- **Results:** sorting, filtering for duplicates, listing a column's values and pivoting are several times faster on number columns with many repeated values (a status, a flag, a foreign key).
- **Results:** the same operations on text, date and binary columns are many times faster on large results, most of all when values repeat or share their first characters (names, paths, codes, the dates of a month), and now use several processor cores, shared between the operations running. When result memory is too full to do this in time, they say so instead of running to their time limit.
- **Results:** column profiles are several times faster on large results: they now use several processor cores.
- **Results:** sorting a result that has finished loading no longer computes its column profile again: another sort column or direction, a further sort column or a Sort text by change keeps the panel's figures as they are, without a moment of "Profiling…" and without reading every row again. Changing the filters, the result finishing loading or running the query again still profiles it again.
- **Results:** two operations on results at once (two sorts, a sort and a pivot, a pivot beside a column profile) now share the processor cores, so the second no longer runs on what the first leaves: two pivots started together both finish a little later than one alone would, instead of one taking three times as long.
- **Results:** search in results, highlights' row matching and Compare Results use several processor cores too, and filtering for duplicates or listing a column's values no longer sorts every row when the column holds few different values.
- **Results:** a pivot's Distinct Count is many times faster on large results (about 4 seconds down to a fraction of a second for 4 million rows), and Compare Results' matching and a column's value list with many different values now use several processor cores as well.

### Fixed

- **Results memory while scrolling:** scrolling through a result with long or wide values, or one whose rows were still arriving, no longer keeps the text of every grid section you scrolled past in memory beyond the results cache limit; only the sections in and near view are kept.
- **Updates on Linux:** a newer release found right after another finished downloading no longer fails its download because cleanup of the older files deleted it.
- **Compare:** comparing two results that no column keys (repeated rows or NULLs, so whole rows are matched) failed with "The results could not be compared."; such results now compare.
- **Pivot:** the Pivot builder could count its source result as 0 rows; it now shows the rows the result holds.
- **Object Explorer:** pinned server shortcuts above and below the tree, including entries in More servers, offer the same full context menu as the server row in view.
- **Connection recovery:** Connect's deferred Explorer focus yields to newer keyboard or pointer input. Rejected native opens fail without blocking cleanup, and cancelled or lost database/password changes cannot leave unverified settings eligible for connection reuse.
- **Startup reconnect safety:** an edited or planted session file can no longer make startup sign in with Windows Authentication or Microsoft Entra unasked, whether to a server Varia did not save or to one you disconnected. Such connections keep their tabs and labels and wait for an explicit Reconnect. On Linux, a session or saved password forged under Chromium's built-in fallback key is refused.
- **Closing with a details confirmation open:** a close, quit or Windows shutdown that goes ahead (after any save prompts) cancels an open connection details confirmation instead of being refused, and keeps the tabs. Reload cancels it as soon as it is chosen, before its own confirmation.
- **Hot exit:** a close after a startup that could not reopen the last session keeps that session as a recoverable copy instead of replacing it, and an earlier failed close no longer refuses every later one.
- **Connection safety:** Database Properties, Table Designer, SSIS, Activity Monitor and other dependent documents no longer follow a replacement connection by server name alone. Drafts stay open, and operations require their original connection target. Legacy documents without that identity must be reopened explicitly after a connection is replaced.
- **Disconnect prompts:** cancelling a running query names the server disconnect action and explains that cancellation cannot undo committed work and may have an unknown outcome. Server transaction prompts default to Cancel.
- **Connection lifecycle:** reload retires obsolete account pins; busy document work and unrelated manual Connect no longer discard startup reconnects. Failed disconnect retains its previous resume preference. Corrected credentials can recover a rejected saved revision after fresh authentication, and transient account-check failures retain their original retryable error.
- **Closing during reconnect:** closing the workbench, including Windows session end after crash recovery, settles automatic reconnect work before saving the tabs and server associations. Repeated failed connections no longer exhaust the pending-attempt allowance.
- **View Dependencies during Disconnect:** pause metadata reads and retain the tree while teardown is in progress. A cancelled or failed disconnect restores explicit reads only for the same connection; stale replies and replacement connections cannot change the retained tree.
- **Fused result reads:** release returned scratch buffers with their working-memory reservation, including before fallback unpacking.
- **Connection authentication:** initial SQL authentication uses a fresh physical session, and Entra connections preserve the configured Application Name. Cancelled or transient guarded opens no longer retire unrelated pooled sessions. Commands and pickers stop admitting new work while a server disconnects.
- Clicking inside selected query text clears the selection and places the caret where you clicked.
- **Execution timeouts on Linux and macOS:** a query whose execution timeout passed while many tabs were connecting at once could run past its timeout and report "Query completed with errors" instead of timing out. Timeouts now stop the query on time.
- **Results:** when a running query fills its result memory budget (or reaches a row limit, or the computer runs low on memory), the grid now says so at once, with the rows read still counting, instead of only after the query ends.
- **Results:** the notice for a running query that has filled its result memory, or that stopped keeping rows because the computer is low on memory, now has a **Stop query** button (Cancel Executing Query for that tab), reachable by keyboard, until the query ends. The row limit you set yourself only says it was reached.
- **Results on a computer low on memory:** sorting, filtering, listing a column's values, profiling, comparing and pivoting a result are now refused when the computer is nearly full, saying it is low on memory, instead of taking more from a computer with none to spare: a large request at once, and work that takes its memory in pieces (long values, many differing cells) for every 64 MiB it holds. A profile first tries again on one thread, which holds less; a pivot's Distinct Count falls back to a slower way rather than take more.
- **Opening several files:** in File › Open, one selected file that could not be read (access denied, removed meanwhile) no longer stops the others from opening; they open, and the message names the file that could not be read.
- **Security:** permission checks in the workbench window and its popouts are now refused like their permission requests (the workbench window may still write the clipboard), instead of being granted by default.
- **No leftover language service on Linux and macOS:** a SQL backend that crashed or was restarted while a query's language service was closing could leave that process suspended in the background. It now always ends.

## [0.8.0] - 2026-11-10

Write SQL with connection\-aware suggestions, reshape results without running the query again, and see more of what your server is doing\.

### New and improved

- **SQL IntelliSense:** Get suggestions for tables, columns and other database objects, inspect identifiers with hover, and see SQL issues in the editor\. Refresh Local Cache updates the schema information when objects change\.
- **Filter results in place:** Use a column's funnel to choose values, search its value checklist, or filter by ranges, NULLs and duplicates\. Filters combine with sorting\. Search, copy, export, profiles and highlights follow the displayed rows; SQL is not executed again\.
- **Pivot and transpose:** Group displayed results and calculate counts, sums, averages, minimums or maximums in a new pivot result\. Transpose turns displayed or selected rows into columns\. Both outputs can be sorted, filtered, copied and exported\.
- **Activity Monitor Processes:** Inspect a live sessions grid with text and column filters, view chips, and switches for system sessions and Varia's own sessions\. Expand more than one overview chart at a time\.
- **Recover a closed query:** Reopen closed queries as unsaved, disconnected copies\. Create a query directly in an editor group, and see whether Execute will run your selection or the entire query\. The status bar also offers Go to Line and insert/overtype switching\.
- **More ways to work with results and errors:** Copy a column's name, fit columns with the keyboard, close results from their toolbar, and jump from a SQL error to its source line when the source has not changed\.

### Changes to everyday use

- **Quicker updates on Windows:** An installed copy in a folder you can write now prepares a downloaded release while you work\. Restart to Update swaps it into place\. Installations for all users continue to use the installer\. Restart verifies the downloaded file again before installing\.
- **Manual updates on macOS:** macOS builds tell you when a release is available and open its downloads page\. They no longer download an update that this unsigned copy cannot install itself\.

### Fixes

- **Tabs, Peek and everyday navigation:** Tab focus, renaming and overflow are more reliable\. Peek shows long definitions in a read\-only editor with Find and SQL hover, and remains usable in narrow panels\. Saved\-connection selection and Object Explorer recovery actions are improved\.
- **Results remain consistent as you reshape them:** Corrected highlight and comparison edge cases, filtered row counts and reuse of filter/sort results\. Numeric pivot sums retain precision up to 38 digits\.

### Things to know

- **IntelliSense uses its own connection:** Connected IntelliSense currently supports SQL Login and Windows authentication\. Entra IntelliSense is not available yet; query execution keeps its existing authentication support\. Query\-session temporary tables and uncommitted changes are not visible to the analysis connection\.
- **Results stay in memory:** Transpose uses at most the first 4,095 displayed or selected rows and reports truncation\. A pivot that exceeds its group or figure limits is refused with an explanation\.
- **More Activity Monitor panes are still to come:** This release adds the Processes grid\. Blocking, Resource Waits, Data File I/O and expensive\-query panes are not shown yet\.
- **Unsigned builds:** Builds remain unsigned, and macOS builds are not notarized\. Your operating system may ask you to confirm that you trust the application\.

## [0.7.0] - 2026-11-08

Explore execution plans, compare results, and arrange your SQL workspace around the way you work\.

### New and improved

- **Graphical execution plans:** Inspect Actual, Live and Estimated plans, open and save \.sqlplan files, and navigate with pan, zoom, fit, an operator outline and a properties inspector\. Available diagnostics include runtime counters, predicates, parameters, memory grants, spills and missing\-index details\.
- **Plan history and comparison:** Retain and pin plan snapshots, reopen them after executing again or closing a query tab, and compare retained or saved plans side by side\. Plan history lasts until the workbench window closes or reloads\.
- **Analyze the results you already have:** Sort by multiple columns without executing SQL again\. Search cells and columns, inspect column profiles and histograms, show row sizes and whitespace, and compare against a previous result\. Copy and export follow the displayed order\.
- **Arrange your workspace:** Split, stack and float query editor groups\. Pin queries on separate shelves and adjust shelf heights\. Move Object Explorer, Results, Messages or Execution Plan panels into their own operating\-system windows and return them to the main window\.
- **Inspect objects and find them faster:** Peek at supported objects' definitions, properties, columns, parameters, dependencies and top rows in a card or document tab\. Search Objects adds fuzzy matching, searches across connected servers and a details pane\.
- **Shortcuts, statistics and memory visibility:** Customize scoped keyboard shortcuts and supported mouse modifiers, with conflict handling, import/export and resets\. Client Statistics compares per\-execution counters, while the status bar shows search\-index and retained\-result memory use\.

### Fixes

- **Safer recovery and more reliable focus:** Preserve restored query text through renderer crashes and Windows session ends, protect newer external file edits when saving restored tabs, and improve docking, detached\-panel focus, tab overflow and workspace restoration\.

### Things to know

- **Plan capture depends on server permissions:** Automatic Actual plan capture requires Extended Events permissions\. Live plans require a supported server and profiling permissions\. Estimating a plan in the query session is an explicit action; the ordinary estimate uses a separate connection\.
- **Bounded, in\-memory analysis:** Results, searches, profiles, comparisons and plan history stay within memory limits\. Varia reports truncation, partial data and estimates\. Builds remain unsigned, and macOS builds are not notarized\.
