# Changelog

## [Unreleased]

### New and improved

- **Cleaner SQL IntelliSense dropdowns, BigQuery completion fixes, and working Refresh Local Cache (`Ctrl+Shift+R`) on BigQuery:** Query editors now disable noisy document-word suggestions (`wordBasedSuggestions`), display right-aligned kind/type metadata via structured Monaco completion labels on both SQL Server and BigQuery, and insert a newline on **Enter** (**Tab** and click accept suggestions) so typing a short table alias such as `t` after a table name is never hijacked by `TABLE` or `TABLESAMPLE`. GoogleSQL completion now restricts post-table `FROM` suggestions to valid clause continuations, preserves hyphenated project and table identifiers (`my-proj-2`) while filtering, boosts exact name matches (ignoring case and backticks) to the top as you type, exits auto-closed backticks cleanly when accepting leaf objects while staying inside for project/dataset chaining, supports **Refresh Local Cache** (`Ctrl+Shift+R` / `⌘⇧R`) on BigQuery tabs with clean status-bar feedback, and invalidates the completion lookup cache immediately when Search Objects builds, refreshes, or DDL updates land.
- **Search Objects indexes are saved to disk, encrypted:** Each part of an index (a database, a server's own objects, a BigQuery dataset) is now saved to your Varia profile as soon as it has been read, compressed and encrypted under a key that only the operating system's key store protects, in files whose names give away nothing about your servers. A BigQuery connection reads its saved index back when it connects: its datasets are searchable at once, the index line says how old they are ("Index saved 2 h ago, checking.") while the build lists them again, and only new, re-created or changed objects have their details read, so a second start of an unchanged project makes no `tables.get` calls and writes no files. Reading a SQL Server index back, after a check against the server, comes next. **Save index between sessions** (on by default) turns it off and deletes what was saved, **Saved index disk limit** (2,048 MiB by default) bounds the space with the least recently used indexes going first, and an index not used for 30 days is deleted. On a system with no key store (Linux without a keyring) nothing is saved unless you turn on **Save index unencrypted when there is no key store**, which Options explains beside the settings. **Clear Saved Search Indexes** in the command palette deletes them all, and the Memory panel's Search Indexer row shows what is on disk and whether it is encrypted.
- **Search Objects keeps SQL Server definitions beside a large BigQuery index, and has a memory limit you can set:** A large BigQuery connection could fill the memory all Search Objects indexes share, after which SQL Server databases were indexed by name only and a search inside procedures, views and functions found nothing. BigQuery now always leaves part of that memory free: its discovered projects' columns and view text stop first (at half the limit), then the billing and starred projects', then its names, so SQL Server's definitions keep room (at least an eighth of the limit) whichever connection was indexed first. When memory does run out, the index line and Search and index details say how many definitions were left out, with what to do, and All servers names the server. A BigQuery index therefore holds less than it could at the default limit (its columns and view text about half of it, less what SQL Server holds), and a large one shows more projects by name only: raise the limit to give both engines more. **Index memory limit** (Options › SQL Server Object Explorer › Commands, 512 MiB by default, 64 to 16,384 MiB) sets that memory; it applies to the next index build, lowering it drops nothing already indexed, and the Memory panel's Search Indexer row shows the limit in force.
- **Faster BigQuery indexing, paced at BigQuery's own limits, with clearer progress:** BigQuery metadata calls are now limited the way Google documents its API (core) limits. Each REST method goes up to 100 requests a second per principal (`projects.list` 10), with up to 250 calls in flight. The old limit of 16 calls in flight for all calls together is gone. The Search Objects index lists 32 datasets and 16 projects at a time and reads 64 objects' details at a time, so large projects index many times faster. When BigQuery refuses a call for its rate limit, that method slows down (to no less than a tenth of its rate) and recovers by itself. The status bar now names what it is counting: "Listing BigQuery datasets N / M", with "~M" while more projects may still add datasets, or "Reading BigQuery object details N / M". It adds "(rate limited)" while BigQuery is throttling. SQL Server indexing and its status are unchanged.
- **Cross-project BigQuery Search Objects indexer, Starred Projects, and Project/Dataset search scope:** BigQuery connections now automatically discover and index objects, columns, and view/routine definitions across all BigQuery projects the authenticated principal can access (default 500 projects, configurable 1–5,000 via **Maximum accessible BigQuery projects** and toggleable via **Index all accessible BigQuery projects**, matching SQL Server's server-wide indexing) in three prioritized waves — billing project first, then starred and discovered project names, then full column and definition details under the shared rate limiter and memory budget while silently ignoring non-BigQuery GCP projects and keeping billed `INFORMATION_SCHEMA` bulk indexing scoped to billing and starred projects. Replaced **Extra projects** on BigQuery connections with BigQuery Studio-style per-principal **Starred Projects** (persisted in `bigquery-connections.json` separately from connection identity, fixing duplicate BigQuery connections in Object Explorer and History, with automatic migration of legacy `extraProjects`), **Star a Project…** (`bigquery.connectionProjects` + typing any verified public/dataset-ACL project ID such as `bigquery-public-data`, with existence and access verification before starring), row star toggles, and ephemeral session-only Object Explorer projects when revealing search hits or referencing projects in open query tabs. Opening **Search Objects…** from a BigQuery project or dataset node now shows a removable Project or Dataset scope chip that clears cleanly when switching servers or searching **All servers** alongside SQL Server.
- **Grouped calm status bar and actionable Memory popover:** The window status bar now collapses the redundant `Ready` and `Connected.` labels into one connection segment whenever the SQL backend is ready and the active query is connected (while still surfacing non-ready backend states prominently), replaces vertical pipe separators with calm group spacing and `1 px` hairline dividers, and condenses SQL IntelliSense and analysis status into one clickable status chip that opens the relevant Options page while keeping polite screen-reader announcements intact. The Memory status trigger now shows the live combined MB total beside its dual rings (falling back to `Memory` at `0 MB` or when unavailable), and **Biggest results** in the Memory popover adds a hover/focus-revealed `×` button per row to release an individual result set (disabled while its query runs) plus **Close all** to release all non-running results across tabs without closing query tabs.
- **Unified `Plan ▾` menu, morphing `Execute → Cancel` and Execution Scope pill:** The modern per-query bar now consolidates **Include Actual Plan**, **Include Live Plan**, and **Display Estimated Plan** into one keyboard-accessible **Plan ▾** menu with distinct custom icons (`execution-plan-actual`, `execution-plan-live`, `execution-plan-estimated`) and active trigger states (`Plan`, `Actual Plan`, `Live Plan`, `Actual + Live`). While idle, **Execute** (**Run Selection** when text is selected) pairs with an anchored scope pill (**All** muted / **Line N** or **Lines N–M** warning-tinted) and hides disabled **Cancel**; while executing, the button morphs in place into an error-tinted **Cancel** button with a live elapsed timer (`1.4s`), keeping focus and split-group independence intact. The classic toolbar keeps its existing separate buttons.
- **Converged Database Properties, SSIS Properties, Search Details, and View Dependencies onto shared inspector primitives:** Database Properties now uses click-to-copy `FactGrid` groups, adds `RatioBar` proportion meters for database space (used vs. available) and memory-optimized memory, renders Files and Filegroups at natural height with zero nested vertical scrolling, and clears stale hover/focus field hints when switching sections. SSIS Properties now uses `FactGrid` for General facts and natural-height lists virtualized against the outer scroll column (zero scroll-within-a-scroll while keeping bounded DOM pools at the 2,048-row cap). Search Objects' details pane and the Object Dependencies dialog's selected-object facts now use compact click-to-copy `FactGrid`s, and unused legacy fact-list CSS rules were removed.
- **Foreign Key & Constraint inspector visuals, BigQuery Routines/Datasets Properties, and BigQuery Peek:** SQL Server Foreign Key Peek cards and tabs now render a visual **Foreign Key Relationship** diagram (`parent.table (cols) → referenced.table (cols)`) with clickable jump-links to both tables via Peek's Back stack plus `ON DELETE` / `ON UPDATE` and Enabled/Trusted pills; Primary Keys and Unique Constraints show a **Key Summary** block with clustered/nonclustered pills; and `CHECK`, `DEFAULT`, and `EDGE` constraints show a copyable **Expression** block, target column, Enabled/Trusted/System-named capability chips, and clean expression display in **Definition**. BigQuery `bigquery.properties` and the unified BigQuery Properties inspector now support **Routines** (free `routines.get`: type, language, determinism, return type, bounded **Parameters** grid, and free definition body) and **Datasets** (free `datasets.get`: location, default table/partition expirations, KMS encryption, collation, time travel, billing model, and sorted **Labels**). Floating **Peek Cards** (`Alt+F12`, `Space`, Ctrl+hover) now work on BigQuery tables, views, materialized views, external tables, routines, and datasets with zero billed queries on open, lazy free `tabledata.list` **Preview Rows**, and **Open as Tab** (`Ctrl+Enter` / `Ctrl+click`) promoting directly into the unified BigQuery Properties tab on the matching section.
- **Unified SQL Server Table Properties inspector and Peek promotion handoff:** Table Properties now uses the shared `ObjectInspectorFrame` shell with a Hero KPI strip (Rows, Total Space with Data vs. Index ratio bar, Columns, Indexes & Keys, Partitions), semantic status pills, a collapsible/resizable Vitals rail, docked Script drawer, zero-height hover/focus field hints, natural-height Partitions/Permissions/RLS grids (zero scroll-within-a-scroll), and canonical tabs (**Overview**, **Definition**, **Storage & Layout**, **Columns**, **Indexes & Keys**, **Dependencies**, **Permissions & RLS**, **Extended Properties**, and **Preview Rows**) that lazy-load read-only catalog tabs only when selected. Promoting a SQL Server table from Peek (`Open as Tab`, `Ctrl+Enter`, or `Ctrl+click`) now opens or focuses Table Properties directly on the matching tab instead of creating a duplicate Peek tab.
- **Unified Peek Card and Peek Tab inspector:** Floating Peek Cards and promoted Peek Tabs now share the unified `ObjectInspectorFrame` layout with canonical tabs (`Overview`, `Definition`, `Storage & Layout` for tables, `Usage Telemetry` for indexes, full-bleed list tabs, lazy `Dependencies`, and lazy `Top rows`), click-to-copy `FactGrid`s with clickable cross-object links backed by Peek's Back stack, signal-first `CapabilityChips`, Data vs. Index and Index Usage `RatioBar` meters, a Hero KPI strip and breadcrumbs on promoted Peek Tabs, persistent `1`–`9` shortcut badges on Peek Cards with focus-scoped `Ctrl+1`–`9` (`⌘1`–`9` on macOS) tab jumping, and a collapsible, resizable right **Vitals** rail remembered separately for Peek Card and Full Tab.
- **Unified BigQuery Properties inspector:** BigQuery Properties now uses the shared inspector shell with `connection › project › dataset` breadcrumbs, semantic status pills, Hero KPIs (Rows, Logical with Active vs. Long-Term ratio bar, Physical with compression ratio, Columns, Location), a collapsible/resizable Vitals rail, `Refresh` and `Script As…` header actions, and canonical tabs (**Overview**, **Definition**, **Storage & Layout**, **Columns**, **Labels**, and **Preview Rows**). Views and materialized views show their GoogleSQL definition immediately in a read-only Monaco editor with Copy and Open in New Query; native, external, snapshot, and clone tables offer an explicit **Load DDL** prompt that estimates and applies BigQuery's cost prompts before running anything; **Columns** renders a filterable full-bleed grid with `PART`/`CLUST`/`REP` badges and expandable nested `STRUCT` rows; and **Preview Rows** lazy-loads free `tabledata.list` rows only when selected.
- `bigquery.properties` now returns structured identity, storage counts, layout metadata, bounded nested schema fields, sorted labels, and free view/materialized-view SQL alongside formatted fact groups from the same free `tables.get` call.
- **Polished Options window:** Tools › Options now opens at `960 × 700` with a resizable navigation rail (`180–340 px`, remembered across sessions). Searching (`Ctrl+E`, `⌘E` on macOS) searches across every page into grouped **Search Results** with match highlighting, tree count badges, clickable page breadcrumbs, and **Modified** filtering with per-row reset (`↺`). **Environment › General** adds **Dark**, **Light**, and **Follow System** theme mode cards plus the palette picker with live preview and custom theme actions; **Fonts and Colors** shows a live Transact-SQL font-size preview; **Apply** saves changes without closing (closing with unsaved edits asks first, and **Reset Page** restores the current page); compact single-line rows keep pages scannable with a hover/focus bottom description panel; **Scripting**, **Commands**, and **Editor Tab and Status Bar** boolean rows use 1-click `True`/`False` switches; and **Shortcuts** uses a slimmer header and inspector.
- **Connect in its own resizable window:** Connect now opens in its own OS window (`900 × 730` by default) with a draggable `320 px` saved-connections rail, remembering its window bounds (falling back safely to default size or recentering if a display is unavailable) and rail width. Favorites are deduplicated out of Recent Connections, live Object Explorer targets show a green status dot, removing a saved entry offers inline **Undo**, newly typed passwords have a show/hide toggle and saved passwords show an inline indicator, **Labels & Custom Properties** stay expanded with quick color swatches, **Advanced** opens inline with live search and a modified-count badge, and the **Connection String** tab adds **Copy** and **Parse & Fill Form** (without importing passwords).
- **SQL Server Agent:** SQL Server connections to a server that runs Agent (not Express or Azure SQL Database) now have SQL Server Agent in Object Explorer, with no setting or environment variable to turn on: Jobs, Job Activity Monitor, Alerts, Operators, Proxies and Error Logs as SSMS shows them for your Agent role, each job, alert, operator, proxy and credential in its own document tab, and a new Getting Started guide, "Schedule work with SQL Server Agent", with a fictional schedule sample. BigQuery connections have no Agent node. The entries below describe each part.
- **SQL Server Agent jobs and service from Object Explorer:** A job's context menu has Start Job at Step…, Stop Job, Enable or Disable, Rename and Delete, and the SQL Server Agent node's has Start, Stop and Restart, which ask first, show their progress and use your Windows account's rights on the server's machine \(Varia on Windows, for a Windows server\)\. Job actions check the listed job's immutable ID, so a replacement job that takes the name is never changed by a stale selection.
- **Job Activity Monitor:** Job Activity Monitor on the SQL Server Agent node's menu \(or its node in Object Explorer, View › Job Activity Monitor, or the palette\) lists a server's jobs live, with their status, last run outcome, next run and how long a running job has run\. Tiles count running, failed, between\-retries and disabled jobs and filter to them; view chips, a filter box and column filters narrow the list\. Select jobs to Start, Stop, Enable or Disable them, or to change their owner or attach a shared schedule to them \(Change owner… and Attach schedule… ask for the login or schedule first\), each as its own request with its own result line, and the Last run chevron shows the selected job's last run below the list\. Right\-click a job for Open, Create Job Like This, Script Job as CREATE, Start, Stop, Enable, Disable and View History; F5 refreshes the list, and when SQL Server Agent is stopped its banner has Start Agent…\. A job you start is followed in the status bar to its outcome, with Stop, even while the window is hidden, and a separate status bar item says when SQL Server Agent is stopped\.
- **SQL Server Agent Properties:** The SQL Server Agent node's Properties opens SSMS's General and History pages: the two auto restart settings and the job history log limits, with a table of how long each job's history lasts under the limits now and under the ones you type. History's Delete old history deletes every job's history older than a number of days, weeks or months after an inline confirmation, separately from OK. Logins below sysadmin, and Managed Instance, see the settings read-only; so does Linux, where mssql-conf sets them and Delete old history still runs.
- **SQL Server Agent job document:** A job opens in its own tab from Object Explorer, Job Activity Monitor \(double\-click or Enter\), Ctrl\+Q or the palette's Open Job…, with its live state, Start \(or Start once at a step\) and Stop in the header\. Edit its General and Notifications settings, see whether Database Mail can send and when an operator is on pager duty, and remove the alerts that run it; Save sends every change as one transaction, and if someone changed the job since you opened it, nothing is saved and a field\-by\-field comparison lets you reload and keep your changes\. New Job creates a job from blank or as a copy of another, and the Script drawer shows SSMS's script for the save\.
- **SQL Server Agent alerts and operators:** An alert or operator opens in its own tab from Object Explorer or the palette, and the SQL Server Agent node's New menu creates them. The alert document sets when it fires (an error number, a severity or a performance counter, with the counter's current values), what it does (run a job, notify operators by e-mail, pager or net send, or a new operator made on the spot) and its options, with its history in the header; a job's New alert for this job… starts one that runs the job. The operator document edits addresses and pager duty and sends a test e-mail through SQL Server Agent's mail profile. Operators and Notifications… shows every alert against every operator in one grid you edit by clicking cells, and Add recommended alerts… creates the usual severity and error alerts the server lacks. Deleting an operator can move its notifications to another one, and alert and operator rows have Enable, Disable, Rename and Delete. Alerts need SQL Server on Windows; only sysadmin can change them.
- **SQL Server Agent job steps:** The job document's Steps page lists a job's steps with where each goes on success and on failure, and edits them beside the list: T\-SQL in an editor that completes against the step's database, with Parse and Open in query window; PowerShell and CmdExec with Run as a proxy; SSIS packages picked from the SSIS Catalog on one page with their parameters and environment\. Drag a step, use Move up and Move down, or press Alt\+Up and Alt\+Down, and the steps that go to it follow; Delete shows which steps now quit reporting failure, with Undo\. Save writes the steps with the rest of the job in one transaction\.
- **SQL Server Agent steps Flow view:** The Steps page's List | Flow switch draws a job's steps as a graph: each step with its type and key field, where it goes on success and on failure (the next step, a Quit, another step, or an End node when the last step would fail the job), the Start step, loops and steps that never run, and the actions you changed since opening the job. Flow checks warn, without blocking Save, about a step that never runs, a loop, a loop with no way out and a last step that goes to the next step, each with its fix. Drag a ✓ or ✗ port onto a step to set Go to step, or right-click a step (Shift+F10) for Edit step, Start job at this step, Make Start step, On success, On failure, Add step after, Move up, Move down and Delete step; Enter docks the step editor beside the graph. Every job opens on List, and the steps are also an accessible tree for the keyboard and screen readers. Flow's Show switch draws a run over the graph: **Run** (any run from History, also through History's Show in Flow) shows the path it took with the order of each edge, each step's outcome and duration (×N for a step a loop ran more than once), the steps it never reached and the failed step's message; **Live run** turns on when the job starts, rings the current step (with a slow pulse) with its time against the usual time and the ways it can go next, and goes back to the previous view when the run ends.
- **SQL Server Agent schedules:** The job document's Schedules section edits a job's schedules in place with SSMS's fields, preset chips \(Every day at…, Weekdays at…, Every N minutes and more\), SSMS's sentence and the next five runs in server time, and, for sysadmin, says whether another job runs during this job's usual duration\. Add finds a shared schedule by name or by when it runs \("night", "every 15 minutes"\) with a preview, or starts a new one; a shared schedule names the other jobs it moves and offers Copy for this job only; Remove detaches a schedule, or deletes it when no job uses it, with Undo until Save\. Manage Schedules opens a Schedules document: a grid of the server's schedules with All, Unused and Disabled views and a filter, an Enabled box that saves at once, and the selected schedule's editor with the jobs that use it, Attach and Detach\. New › Schedule… on the SQL Server Agent node creates one\. Every save checks that nobody changed the schedule since it was read\.
- **SQL Server Agent Schedules Timeline:** The Schedules document's Timeline view draws when each job runs over the next 24 hours or 7 days, each run as long as the job usually takes, and flags and lists runs of two jobs that overlap, with a link to the schedule. Zoom and scroll it, hover a run for its details, and click it (or press Enter) to open the job. The next runs Varia shows everywhere now match what SQL Server Agent computes, including windows that cross midnight and every-N-weeks and every-N-months schedules.
- **SQL Server Agent proxies and credentials:** A proxy opens in its own tab from Object Explorer \(Enter, double\-click or Properties\), and New Proxy… on the Proxies folders or Proxy… in the SQL Server Agent node's New menu starts one\. One screen sets its name, credential, description and enabled state, the subsystems it is active to and who may use it besides sysadmin, and lists the job steps that run as it\. A new credential can be created right there, with its password typed into masked fields that send it once on Save and keep it nowhere\. A credential opens from Security › Credentials with the proxies and job steps that use it; Change identity and password sends both together, as SQL Server requires\. Proxies can be renamed and deleted from Object Explorer, and the Script drawer writes `<secret>` in place of a password\.
- **SQL Server Agent overview:** Agent Overview on the SQL Server Agent node's menu or the palette shows a server's Agent at a glance: its state and service account, tiles for jobs, recent failures, running jobs and alerts, and health checks for failed jobs, job owners that cannot log in, jobs that notify no one, history that keeps less than a week, missing recommended alerts, Agent mail and unused schedules. Each check names the jobs or schedules it found, and its fix opens the editor that fixes it (Change owner, Notifications, Agent Properties, Add recommended alerts and so on); logins below sysadmin see the checks their role can read, and the rest say why they were not checked.
- **Unsaved SQL Server Agent documents survive a restart:** A job, schedule, alert, operator, Operators and Notifications, proxy or credential document with unsaved changes is kept by hot exit and AutoRecover like an unsaved query. It reopens with your changes, and once its server connects it reads the object again with your changes on top, so you can save them; passwords are never kept.
- **Create Job Like This:** Create Job Like This… on a job's menu, in Job Activity Monitor and in the palette \(and New Job's Copy an existing job\) opens a new job filled from that job, steps included, saved disabled unless you tick Enable when saved\. Its Changes from source section replaces text across the copy \(names, commands, package and output paths\) with a preview of each match, shows each step's database, command or package with what differs from the source marked, and shares, copies or leaves out each schedule; Compare with source lists every difference\. History and the alerts that run the source are not copied\.
- **Create several jobs:** Create several… on Create Job Like This's Changes from source turns the copy into a table with one row per new job\. An empty cell uses the copy's value, shown grey, and a typed one changes that field for that job only; Columns adds any other field of the job, a step or a schedule as a column\. Add row, Duplicate row, Paste rows \(copied from a spreadsheet, one column per visible column\) and Fill names \(a pattern such as `ETL – {package}`\) fill the table, and Open full editor opens one row as a job tab whose changes come back to the row, listed with Reset\. Rows whose name is taken or that New Job would refuse are flagged and skipped; Review and create then creates each job in its own transaction with its own result, created rows lock with Open, and Enable the created jobs enables the ones saved disabled\.
- **SQL Server Agent in Object Explorer follows changes:** An expanded Jobs folder shows each job's state live: **Running · step n/m**, **Between retries**, **Suspended** or **Failed** for a failed last run, and a job disabled elsewhere is dimmed, without Refresh\. The SQL Server Agent node and its folders list again by themselves when Agent XPs or the service state changes, or when jobs, alerts, operators or proxies are created, renamed or deleted elsewhere, keeping what is expanded and selected\.
- **Log File Viewer for job history:** View History on a job, the SQL Server Agent node or the Jobs folder \(also in Job Activity Monitor and the palette\) opens a server's job history as runs, newest first, with each run's steps and the selected row's full message\. Check the jobs to show under Select logs, and narrow the list by window \(24 h, 7 days, 30 days, All\), outcome, message text or step\. Delete History deletes the checked jobs' history, all of it or only rows older than a number of days, weeks or months, after a confirmation\.
- **SQL Server Agent error logs:** View Agent Log on Object Explorer's Error Logs folder or one of its logs opens the Log File Viewer on that log, and sysadmin can check Current and the archives under Select logs\. Their rows show newest first with the selected row's full message, filtered by the same window and message text as job history\. Recycle starts a new Agent error log after a confirmation \(not on Managed Instance\)\.
- **A job's history in its document:** The job document's History section shows the job's runs in place: a sparkline of the last 14 runs' durations with the job's usual time \(the median of its last 10 successful runs\), All or Failed runs, and the selected run with who started it, its outcome, its steps and the failed step's full message open, with Copy, Edit step and Start at step\. An SSIS step's execution link opens that execution's SSIS Catalog messages in a query window\. While the job runs, History shows the run live like a CI run: the time so far against the usual time, each step's state and Stop\.
- **SSIS runs in one document:** The Integration Services document drills down in place instead of opening a tab per report: the catalog's operations, a package's runs \(the package node's Executions\), and one run \(Open on an operation, the package node's Last Execution, or an SSIS step's execution link in a job's History\)\. Back and Forward \(Alt\+Left and Alt\+Right, Cmd\+\[ and Cmd\+\] on macOS, the mouse's back and forward buttons\) and a location bar move between them without reading again\. A run's page shows where it failed, this run against the package's recent runs, a task timeline against each task's usual time \(a task shows only its messages\), chips for the SSIS events it logged \(PreValidate, PreExecute, Warning, Error and the rest\), its first error, the messages in a results grid with column filters filling the page with the selected message shown whole beside it, and on Details the parameters it used\. A purged execution, a server without the SSIS Catalog and a login without access are said in the page\.
- **SQL Server Agent refinements:** Object Explorer's Error Logs show their dates in the Log File Viewer's format; the palette's Enable and Disable are named for what is selected \(Enable Job, Disable Alert, Enable Login\); the SQL Server Agent node's Start, Stop and Restart are greyed with the reason on a failover cluster instance and while one of them runs; and a member of SQLAgentOperatorRole can enable or disable a schedule another login owns in the Schedules document\.
- **Load a job step's script from a file:** A PowerShell or CmdExec step's **Load from file…** opens a script from your computer \(`.ps1`, `.psm1`, `.psd1`, or `.bat` and `.cmd`, or any file\) in place of the step's command, as SSMS's Open… does\. One Undo takes it back; a file longer than a step's command may be \(100,000 characters\), or one that is not text, is refused with the reason\.
- **Google BigQuery:** Varia now connects to BigQuery beside SQL Server: sign in with the Google credentials you already have (Varia keeps no Google secret), browse projects and datasets in Object Explorer, edit GoogleSQL with highlighting, IntelliSense and errors from free dry runs, run queries and scripts in a session per tab with the cost estimate always beside Execute, keep large results windowed in BigQuery instead of truncating them, and follow, cancel and re-open jobs in Job History. SQL Server-only features are hidden on BigQuery connections. The entries below give the detail; Help › Getting Started has a new **Connect to BigQuery** guide, with a fictional sample of where a result's rows stay, and docs/bigquery.md lists what BigQuery support does not do yet.
- **Connect to BigQuery:** The Connect dialog's new Server type chooses SQL Server or BigQuery, opening on the one you used last; switching keeps each type's fields, and Undo switches back\. For BigQuery, choose how to sign in \(gcloud credentials, a service account key file or identity federation, picked with Browse…\), see which account that is, then pick the project and default dataset from lists of the ones you can see\. Advanced sets Maximum bytes billed, a service account to impersonate and extra read\-only projects\. BigQuery connections are saved, starred and labelled like SQL Server's and listed by project; a query tab shows the project, account and default dataset, which its Dataset box changes\. Running BigQuery queries and browsing datasets in Object Explorer come in a later update\.
- **Peek for keys, constraints and a table's indexes & keys:** Object Explorer's Peek now describes keys \(primary keys, unique constraints and foreign keys, with their key columns, referenced table, referential actions and enforcement status\) and constraints \(check, default and graph edge constraints, with their target column, expression and enforcement status\)\. A table's Peek also includes an **Indexes & keys** list summarizing its primary key, foreign keys, unique constraints, indexes, check, default and edge constraints, and triggers without requiring `VIEW SERVER STATE`\. Its Summary column brackets names as scripts write them, and a summary whose columns did not all fit ends in `…`; a key's or constraint's type reads as Primary key, Check constraint and so on\.
- **Peek's lists are grids:** Peek's Columns and Parameters tabs, and its Index columns, Events, Files, Server roles and User mapping lists, are now grids you can select, sort, filter and copy from, as Query Output's are; in a Peek tab they fill the page and Save Results As writes them. Columns lists each column's type, nullability, key, identity, computed expression and default, and Parameters each parameter's type, direction and default, each with a Definition you can paste into a CREATE statement. Copy on the Properties pane's context menu copies the selected facts, or all of them, as name and value.
- **The column profile follows your selection:** The cards of the columns selected in the grid are highlighted, the active column's card scrolls into view as you move, and clicking a card selects its column in the grid. **Selected Columns Only**, on the panel's filter button or the results ⋯ menu, lists just the selected columns, and holding Ctrl (Cmd on macOS) over the panel peeks at them, or at every column while Selected Columns Only is on, until you let go.
- **Test Connection:** Connect's footer has a Test Connection button that signs in with the form as it is and reports the result inline, with the databases the login can see, without saving anything or opening a connection\. Escape or Stop ends it\.
- **Save says what it does with a password:** With Remember password checked, Save checks a newly typed password with the server, then remembers it; a wrong password saves nothing\. A note under Password and Save's tooltip say what Save keeps, and Save confirms what it saved\. Unchecking Remember password and saving forgets the saved password, as Connect does\.

### Changes to everyday use

- **Calmer Results toolbar, Smart 2-Bar header, and right-aligned numeric columns:** The Results toolbar now collapses **White space** and **Sort text by** into compact popover triggers that expand into tinted state chips (`Spaces`, `All`, `Chars`, `Bytes`) only when non-default, removes wireframe boxes around icon groups and output view tabs in favour of tonal hover/pressed fills and hairline dividers, and keeps the run summary unclipped at desktop widths. In Results as Tabs, a solo Table without a Pivot or active filter chips hides the redundant view bar and moves its row/column facts and **Save Results As** inline onto the result tab strip (reclaiming 28 px), expanding the view bar automatically when a Pivot, comparison, or filter chip is present. Numeric columns in results grids now right-align with tabular figures and semibold column names paired with muted monospace SQL types (transposed views remain left-aligned).
- **Object Explorer 2-line server bands, aligned seams, and tree polish:** Connected servers in Object Explorer now appear as flush `44 px` 2-line bands—both in the tree and when pinned above or below while scrolling—keeping the server name, environment tag, and connection dot unclipped on the first line while showing host/version/login details, live Agent job chips, the active-query indicator, and offline recovery actions on the second line. Connection colors draw a subtle top/bottom hairline and soft directional wash instead of a thick left stripe. The Object Explorer header stays on a single row down to minimum dock widths (`Connect`, `Refresh`, `Collapse All`, and a `⋯` panel menu holding `Disconnect`, `Remove`, `Stop`, and layout actions), `Filter Settings` and `Group by Schema` sit inline beside the search box, and both rows align horizontally with Document Tabs and the query bar across the splitter. Nested tree rows show `1 px` vertical indent guides (`tree.indentGuidesStroke`), primary-key columns display a compact `PK` badge with column names prioritized over type sublabels, static system folders are gently muted, and the connected-server count stays pinned right in the footer while long listing scopes ellipsize.
- **Document tabs above per-query bars, refined 2-line tabs, and connection-colored query bars:** Document tabs now sit above each SQL document's own `QueryBar`, so switching between SQL queries and non-query tabs (Activity Monitor, Table Designer, Properties, XML/JSON values) never jumps tabs vertically, and split editor groups each show and control their own server, database, and execution state (clicking a control in an inactive group's bar activates that group first). - **Calmer resting chrome, thin scrollbars, and workbench P0 fixes:** Resting input and secondary button outlines are softened (`#3a404d` Dark / `#c2c8d4` Light) while hover outlines and focus rings stay crisp, scrollable workbench panes use thin themed scrollbars outside Windows High Contrast, and the header's Standard toolbar groups Connect, file commands, and Activity Monitor with hairline dividers and a subtle unsaved indicator on Save. Also fixes the empty Query Output tablist dot before a run, the Memory panel's Biggest Results tab-name truncation, and false-positive warning bars on uniform-sized rows in the results row-size gutter (only true outliers—over half the largest row and at least 4 KiB or 2.5× the mean—now highlight in amber).
- **Larger results fit in memory while they load:** A result is now compressed as it loads, once it passes 1 MiB, instead of only after it finishes and sits idle. A single result can therefore be at least twice as large, and often several times larger depending on how well its data compresses, before it reaches its memory limit and is truncated. Loading takes as long as before.
- **Copy and save have their own column header settings:** Options › Query Results › SQL Server › Results to Grid now has **Include column headers when copying the results** (off by default) and **Include column headers when saving the results** (on by default) instead of one setting for both, so Save Results As writes a header row unless you turn it off. - **Properties lists are results grids:** Table Properties' Permissions, Partitions and Security Predicates, and Database Properties' Files and Filegroups, are now drawn like query results: select cells, rows or columns, copy with or without headers, sort by a header, resize or fit columns, and Save Results As from the grid's menu. - **Sorted and filtered grids are compressed too:** A large result on screen whose grid is sorted or filtered is now compressed once idle like any other, and packing to make room for a new query can take it. - **Search Objects knows column types and keys:** The Search Objects index now also keeps each column's and parameter's type and flags, and each index's, key's and foreign key's columns, ready for the query editor to use. - **Search Objects holds more definitions:** With definitions indexed, those of 512 characters or more (procedures, functions, views, triggers, plan guides, and long constraint and computed column expressions) are kept compressed, at about a seventh of their former size, so far more of a large server's definitions fit before Search Objects starts leaving them out. - **More rows fit in result memory:** Compressed results take less memory, so more of them fit before Varia has to make room: about a third less for a typical query and for results of numbers and dates, less for long text. Scrolling a compressed result is as quick as before; a sorted view's screen of it takes a millisecond or two longer.
- **Smoother scrolling of a sorted compressed result:** Scrolling a sorted or filtered grid of a large compressed result, and Find in it, now reuse the memory each read unpacks into instead of allocating it anew, so scrolling no longer pauses for memory clean-up every other screen.
- **Animations play unless you ask Varia to follow the system:** Menus, dialogs, hover fills, spinners and the live dot now animate even when the operating system asks for reduced motion. To have Varia follow that preference again, turn on Tools › Options › Environment › General › Reduce motion when the system asks; popouts and dialog windows follow it too.

Entra IntelliSense is not available yet; query execution keeps its existing authentication support\. Query\-session temporary tables and uncommitted changes are not visible to the analysis connection\.
- **Results stay in memory:** Transpose uses at most the first 4,095 displayed or selected rows and reports truncation\. A pivot that exceeds its group or figure limits is refused with an explanation\.
- **More Activity Monitor panes are still to come:** This release adds the Processes grid\. Blocking, Resource Waits, Data File I/O and expensive\-query panes are not shown yet\.
- **Unsigned builds:** Builds remain unsigned, and macOS builds are not notarized\. Your operating system may ask you to confirm that you trust the application\.

## [0.7.0] - 2026-11-08

Explore execution plans, compare results, and arrange your SQL workspace around the way you work\.

### New and improved

- **Graphical execution plans:** Inspect Actual, Live and Estimated plans, open and save \.sqlplan files, and navigate with pan, zoom, fit, an operator outline and a properties inspector\. Available diagnostics include runtime counters, predicates, parameters, memory grants, spills and missing\-index details\.
- **Plan history and comparison:** Retain and pin plan snapshots, reopen them after executing again or closing a query tab, and compare retained or saved plans side by side\. Plan history lasts until the workbench window closes or reloads\.
- **Analyze the results you already have:** Sort by multiple columns without executing SQL again\. Search cells and columns, inspect column profiles and histograms, show row sizes and whitespace, and compare against a previous result\. Copy and export follow the displayed order\.
- **Arrange your workspace:** Split, stack and float query editor groups\. Pin queries on separate shelves and adjust shelf heights\. Move Object Explorer, Results, Messages or Execution Plan panels into their own operating\-system windows and return them to the main window\.
- **Inspect objects and find them faster:** Peek at supported objects' definitions, properties, columns, parameters, dependencies and top rows in a card or document tab\. Search Objects adds fuzzy matching, searches across connected servers and a details pane\.
- **Shortcuts, statistics and memory visibility:** Customize scoped keyboard shortcuts and supported mouse modifiers, with conflict handling, import/export and resets\. Client Statistics compares per\-execution counters, while the status bar shows search\-index and retained\-result memory use\.

### Fixes

- **Safer recovery and more reliable focus:** Preserve restored query text through renderer crashes and Windows session ends, protect newer external file edits when saving restored tabs, and improve docking, detached\-panel focus, tab overflow and workspace restoration\.

### Things to know

- **Plan capture depends on server permissions:** Automatic Actual plan capture requires Extended Events permissions\. Live plans require a supported server and profiling permissions\. Estimating a plan in the query session is an explicit action; the ordinary estimate uses a separate connection\.
- **Bounded, in\-memory analysis:** Results, searches, profiles, comparisons and plan history stay within memory limits\. Varia reports truncation, partial data and estimates\. Builds remain unsigned, and macOS builds are not notarized\.
