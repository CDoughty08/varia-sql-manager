Comparison results: UX options

Design reference for reworking the Differences grid (results.diff and its grid). It uses the Varia Dark and Light palettes and Compact metrics, as the other results-pane mocks do. It is not production code: the diff is computed in the page from invented rows, and the grid is a stand-in for GridView. Try the Match rows by list, the direction swap, the filter chips, F8 for the next change, and click cells and rows to see selection layered over the diff colours.

What each of your points becomes

#Your pointIn the proposed look
1Emphasize the cells that changedA changed cell gets a strong tint and shows old → new. Unchanged cells in a changed row fade to muted text. The header of a column that has changes gets a blue underline and a dot, so a change off-screen to the right is still visible.
2Change / R1 / R2 are not dataThey become a gutter like the grid's row-number column: a 3px colour bar, a + / − / ~ marker and the row number. Hovering it gives “Row 3 in Sample Query, row 4 in Awesome Query”. They are not columns: they are not sorted, filtered, profiled, copied or saved. A copy can offer “with Change column” explicitly.
3Selection and hover hide the diff coloursDiff colour is the cell's background colour. Hover and selection are translucent layers on top (17% accent for a row, 12% plus a 1.5px outline for the active cell), so a selected added row is still green underneath. Try it on any tinted cell.
4“Column Profile Result 3” liesOpen Profile: the panel reads Column Profile · Comparison with “Sample Query → Awesome Query” under it, and each column card shows its changed / added / removed / same cells instead of generic value stats. In a menu, tab and Save the comparison keeps its own name.
5Matching rows should still be in the diffThey are. Context is All rows (the default) or Changes only; in Changes only, unchanged rows collapse to “⋯ 6 unchanged rows” bars that expand on click. The Unchanged chip hides them entirely. No “N rows of context” setting: it was confusing and the two choices cover the need.
6Highlight cells, not rowsChanged rows carry no row colour at all, only cell tints and the gutter bar. Rows that exist on one side only are different: every cell is new or gone, so they take a faint wash (switch to Gutter only to see the strict version).
7Compare order is the direction, one row per entryOne row per entry is the default: a changed row shows once, with each changed cell as old → new. The sides bar reads like a diff header (− Sample Query ⇄ + Awesome Query); the swap button reverses added and removed. Two rows (−/+) stays available for people who want git's unified shape.

Other things I noticed

Matching is the real problem in your sample

Rows matched by test, and test is the column that differs (1 vs 2), so nothing matched: one removed, one added. That is correct but unhelpful. Open Match rows by (Your sample query data), choose Row position, and it becomes one changed row. The menu is a checklist like the filter menus: tick several columns for a composite key (try customer + status on Orders). The footer today says “rows matched by test” without any way to change it.

Proposal: a Match rows by menu in the toolbar (Row position, or one or more key columns), with the key columns marked by ⚷ in their headers.

Uncertain matches: two different cases

≈ Repeated key is a real ambiguity: the key appears more than once on a side, so rows are paired in order. The gutter shows ≈ with the explanation, and a chip counts them. Try Repeated keys in Data (sku W-100 appears twice).

? Possible match is only a hint: a removed and an added row share most other values, so the key probably changed. It shows a strip with a one-click Match by row position, and never changes the counts. Try Your sample query with the test key. A row with different data is simply removed or added, with no hint.

Navigation through changes

Previous / Next change (Shift+F8 / F8) jumps cell to cell, wrapping, and says “Change 2 of 5” in the toolbar. A scroll strip on the right marks where changes are, like an editor's overview ruler.

Noise columns

server_time differs on every run. An Ignore columns… list (remembered with the comparison) would drop such columns from matching and from the change count. Not drawn here: it needs its own design for the paired-column rule.

Summary and notices

The orange sentence in the footer becomes four clickable chips (counts that also filter), and “Filters and sorts on the inputs were not applied” becomes a dismissible information line, not a warning colour: nothing is wrong.

Tab and name

“Differences: Sample Query → …” is cut off. Show the two names in the toolbar's sides bar (full width) and let the tab say Diff: Sample Query with the full name as its tooltip.

Not in this mock

  • Side-by-side layout (two grids, scrolling together).
  • Intra-cell text diff for long strings (highlight the changed characters).
  • Copy / Save as a patch or with the Change column.
  • A soft-difference style (text equal by collation, “~”) is drawn as a dashed underline in the real grid.
